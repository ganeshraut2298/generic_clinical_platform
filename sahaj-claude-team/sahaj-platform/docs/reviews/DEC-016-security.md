Reviewer: security-reviewer (read-only), 5 Nov 2026. Saved by the tech lead. Reviewed by reading; nothing was run.

**Verdict: PASS (security), with conditions.** No Critical or High. 4 Medium, 7 Low, 5 Info. **GO, conditionally, for a developer machine. ## Info
I1 BCrypt runs before the DB check, so "admin exists" is slower than "off" (only visible to callers past G1-G5). I2 `@Transactional` on a `@Bean` class: endpoint test mocks the service; QA T6/T8 on a real context cover it. I3 SQL accepts any BCrypt cost; Java enforces 12. I4 The bodyless 500 is not in admin.yaml: architect adds it. I5 build-helper-maven-plugin pinned 3.6.1 while ADR-008 says "managed by parent": drop the version or update the ADR.

## Passed
Absent from the production build by construction (separate source set, separate target directory, no profile activation, no `.mvn/maven.config`); C1-C5 and G1-G5 implemented as designed and fail closed; forwarding headers never read (presence refuses), IPv6-mapped loopback handled, Host exact match, `Origin`/`Sec-Fetch-*` refused, no method override, path normalisation covered; reserved-path filter registered before Spring Security and answers identical bytes; controller re-checks the gate; app connects only as sahaj_app; one-time response, no stored credentials, any existing admin closes the endpoint for good; SQL function correct (SECURITY DEFINER, `search_path = pg_catalog, pg_temp`, no dynamic SQL, constant email and name, value-free messages, advisory lock and re-read, ACL, self-check); password SecureRandom 24 chars (~140 bits) with BCrypt 12 through the shared provisioning; TOTP AES-GCM bound to admin id, secret zeroed; redacted `toString()` everywhere; rate limiter after the gate; extraction refactors keep the password policy.

## Done well
Build-time exclusion as the primary control after recognising the default `dev` profile weakens runtime checks; rejecting on the mere presence of forwarding headers; Host plus Origin/Sec-Fetch against rebinding and CSRF; email and name constants inside the definer function; a self-checking SQL callback with a database-name guard; ciphertext bound to the pre-generated admin id; reuse of seed and enrolment code; the limiter placed after the gate.

## Conditions for use on a developer machine
1. Contract approval line added and the human prerequisites done (M4). 2. M1 fixed (at minimum `xfwd`); until then no `ng serve --host 0.0.0.0`, port proxy, tunnel or published container port while the flag is on. 3. Run only `mvn -f backend/pom.xml -Pdev-tools spring-boot:run "-Dspring-boot.run.arguments=--sahaj.admin.dev-sample-enabled=true"`; never put the flag in an env var, `.env` or an IDE run configuration. 4. Restart without the flag after the call. 5. Keep the dev-tools jar off every shared machine.
