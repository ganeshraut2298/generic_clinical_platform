## Checked and passing
- **Authorisation:** all 61 IPD handlers carry exactly one of `@ScopeGuarded` or `@ScopeExempt` (checked by hand); every guarded service calls `ScopeGuard` (detail, deposit and charge under the clinic lock, transfer, discharge sheet, signoff and discharge, nursing and vitals under the admission row lock, EMR, order and stop, MAR, dose prepare and record re-checked under the lock after the PIN step, escalations); by-id routes resolve the order or escalation first so another clinic's id gets 404; check order is role, module Off, 404, `outside-scope`; the scope is built from the signed-in user, the membership re-read, `ipd.config`, assignments and grants only; switch off means ALL for NURSE; switch on means WARDS or NONE (NONE is never all); VISITING_DOCTOR 403; a NURSE with no active membership 403; `effectiveRole` narrows on either role (fails closed).
- **Lists:** the Admitted list is filtered before any patient, bill or flag read; the bed board does not read the patient of an out-of-scope bed (`outsideScope: true`, null fields); Safety board, summary, Medicine round and banner are computed on `visible`; `otherWardsPastTarget` is a bare count; OWNER and DOCTOR are never narrowed; clinical events use a SQL predicate and `ADMITTED`.
- **Break-glass:** only a NURSE by token and membership with a scope narrower than ALL; the reason is one of three keys; `confirmed` must be boolean true; the admission row lock re-checks "already in scope" and "live grant", so two taps make one grant; `opened_at` and `expires_at` are stamped by the trigger from `clock_timestamp()` (the app has no insert grant on them; a check enforces 30 minutes); liveness in SQL at request start and again under the lock; no extend, edit, delete or truncate; review by an owner only (self-review refused by service, trigger and check); the guarded update gives 409 on a repeat; the database clock stamps `reviewed_at`; unreviewed grants stay listed; on open one transaction writes the grant, the `bg` entry (fixed text and `grant_id`), the record-access row (ids only) and the audit event (ids, key and end time); the cursor is opaque base64url of 24 bytes, strictly decoded and tenant-bound.
- **Database:** ENABLE and FORCE RLS on both tables; revoke all then column-level grants; `id`, `tenant_id` and all time columns never writable by the app; trigger functions SECURITY INVOKER with a fixed `search_path`, execute revoked; `ward_assignment` can only be ended, once, with the database time; composite tenant keys; `clinical_event.grant_id` restricted to kind `bg`; SQL uses named parameters, the `uuid[]` literals are built from `UUID` objects only.
- **Minimisation and logging:** the 403 has a fixed type, title and detail; the handler writes only those and the status; `logRefused` logs ids and the handler name; when the scope cannot be built the request fails with a WARN of ids and a generic 500, never ALL; records that carry a name, bed or UHID override `toString`; audit rows hold ids only.
- **Input:** `ScopeStrictJsonModule` refuses unknown fields with `malformed-request` and no echo; UUID parsing; `limit` 1 to 25; membership ids capped at 100, unique, active NURSE members of the tenant; the ward is checked with a 404.
- **Frontend:** no innerHTML or `bypassSecurityTrust*`, no web storage, no console in `features/ipd`; `ScopeRefusals` carries `{admissionId, write}` only; the Nursing sheet clears on refusal; the Emergency access sheet clears the names on a 403. **Tests:** fictional data. **Dependencies:** none added.

## Re-check after the fix pass (11 Nov 2026): PASS
Reviewed by reading only (no builds or tests). No new Critical, High or Medium. All five code fixes are in place and sound.

**Answers**
- **1-minute pre-filter (F-1):** it can hide a live grant only if the database clock steps back more than one minute inside one transaction, and then it fails closed (JdbcWardScopeRepository lines 52, 62). `now()` is fixed at transaction start, so a long transaction only loosens the bound. App-versus-database skew is irrelevant: both times are read on the database. It removes rows only and can never keep an expired grant alive.
- **ACTOR_ONLY:** chosen only when wards and grants are both empty; equal to the old predicate in that case; she gets all her own entries and nothing else (pinned by `JdbcClinicalEventRepositoryScopeTest` and `ScopeReviewFixIT`). Her own entries on admissions now outside her scope still show name and bed (SEC-3, human).
- **unnest:** same results for empty lists (no rows, false for NULL) and for duplicates (semi-join); array text built from `UUID.toString()` only and bound as a parameter, so no injection.
- **Picker audit row:** constant action and entity type, null entity id, `{"count": N}` only, actor from the principal, written last in the same REPEATABLE_READ transaction (`Propagation.MANDATORY`); a failure gives 500 and no list; 401/403 throw before the write, so nothing is written.
- **Guard before state:** another clinic's id gets 404 before the guard; the guard then runs under the admission lock before the ADMITTED check, so an out-of-scope nurse learns nothing of the patient's state from the error. Inside her clinic, 403 for an existing id and 404 for a missing one (accepted by AC 14; ids are random UUIDs).
- **Owner token:** built only when token role and membership are both OWNER; SHA-256 truncated to 22 characters; one bounded statement.
- **QA tests:** fictional data only; the audit-failure trigger is limited to the test's own tenant and action and dropped in `finally`; the 500 body is checked for no list, name, id or exception text.
