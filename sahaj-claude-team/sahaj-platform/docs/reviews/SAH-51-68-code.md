## What checked out (static)
- **Module boundaries clean.** No billing or ipd import in opd; no ipd import in billing; no opd application/infrastructure/web import from ipd, billing, patient or platform; no opd import in patient. Every reach is an `opd.api` port (EmrIpdOrderPort, EmrRoundPort, EmrEmergencyPort, EmrVitalsSource, EmrAdmissionRequestPort, EmrVisitChargePort) or `patient.api.PatientClinicalUpdatePort`. FinishConventionTest fences the contributors (ArchUnit). ModularityTests not run by the reviewer.
- **Signed-record trigger compatibility.** Every write path that can touch a SIGNED row is guarded by `status = 'DRAFT'` or in the allow-list. SAVE_PRINT bumps no revision; LINK_PATIENT is ER-only, null to value, no updated_at; MARK_SIGNED is the DRAFT→SIGNED update. `jsonb - text[]` valid on PG 16; BEFORE row triggers supported on partitioned tables.
- **Grants match the statements.** emr_record column grants cover MARK_SIGNED, TAKE_HOLD, RELEASE_HOLD, SET_FINGERPRINT, SET_REFERRAL, LINK_PATIENT, MARK_ADVISED, SAVE_FORM_REFS. INSERT_ADDENDUM, INSERT_REQUEST and the round_note insert list exactly the granted columns; id, tenant_id, created_at from defaults; RETURNING id covered by table-level select. follow_up and appointment use table-level grants; emergency_case.sent_to_opd_visit_id granted.
- **ON CONFLICT targets exist:** round_note `uq_round_note_tenant_admission_date`; bill_item plan lines `uq_bill_item_tenant_bill_source_key`; follow_up unique source_visit_id.
- `make_interval(secs => :seconds)` takes a double; boolean `:takeOver` valid in the OR.
- **Contract conformance.** Problem slugs and statuses match opd.yaml 0.6.1; sign_result stores no prints, prints recomputed on replay; EmrFinishBlocker, SignOutcome, Effects, FinishPrint and the choices body match the schemas (response details checked for sign, addenda, admission-request and FinishModels shapes only).
- **Fixed-order mechanics.** ER case locked before the record (D1 step 1); replay check before revision and hold checks; markSigned clears the hold; ER lock order matches the ipd admission (IPD lock, case, request, record), no cycle found.
- **Billing.** findEmrLines filters `source_kind = 'EMR'`, so dental EMR_PLAN lines survive syncEmrLines; label and key lengths validated.
- **Frontend.** No localStorage/sessionStorage/IndexedDB in emr or ipd features; no console logging; beforeunload wired; idempotency key kept per identical body and renewed when the body changes; hold renewed on a clean tick; emr-record-held and emr-record-signed turn the screen read-only.
