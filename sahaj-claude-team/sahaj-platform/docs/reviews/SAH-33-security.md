## Info
I1 Cursor is plain base64 of `micros.seq`, unsigned; harmless because queries are always tenant-scoped; reword the Javadoc/contract to "a cursor that does not decode is refused". I2 Trigger does not check that `acknowledged_by`/`closed_by` is a DOCTOR/OWNER member (no FK; only the app writes them). I3 `reopened_at := now()` (transaction start) while other stamps use clock_timestamp(): safe direction. I4 Four NOT VALID checks: clean the test data and validate them in a migration before production. I5 Reading the board writes no record-access row (accepted, OQ-33-8); retention undecided (OQ-33-16, ADR-006 Q10). I6 The plan textarea has no client-side 1,000 limit/counter (add). I7 Each membership re-read loads the whole team list (`TeamMemberLookup.findAll` then filter): add a single-row `findActiveByUserId` query.

## Passed
Tenant isolation (FORCE RLS, composite FKs, immutable raised_at/by, tenant and role only from the session, 404 across clinics, displayNames tenant-scoped); authorisation three times per endpoint and the stricter view when token and membership disagree; the trigger enforces the whole state machine (timestamps not granted, exact +1 version, score/risk never fall, DONE final even for the owner, senior_calls rules, CLOSED_AT_DISCHARGE rules); one lock rule and discharge ordering; replay rules; input validation (raw cap 4,000, NFC, control/bidi, 1,000 code points, JSON integers, limit and cursor checks); generic 500s; privacy (fixed event templates, minimal audit, redacted toString, privacy ITs); read-only and module Off; frontend (no innerHTML, storage, console; UUID-only URLs; counts-only polls); no secrets, no new runtime dependencies.

## Done well
Timestamps belong to the database; the trigger mirrors `EscalationState` and is tested directly as app and owner; roles checked three times and buttons shown only when both roles allow; clinical text kept out of logs and events with privacy ITs; concurrency ITs on the real races; no false claims to clinicians; clean keyset pagination.
