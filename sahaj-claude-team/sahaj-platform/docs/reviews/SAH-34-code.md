## Confirmed
- **Scope rule:** OWNER, DOCTOR, FRONT_DESK, BILLING and PHARMACIST are ALL; a NURSE is ALL while the switch is off and WARDS or NONE when on (NONE never falls back to ALL); VISITING_DOCTOR is refused everywhere; no active membership gives 403 for NURSE and VISITING_DOCTOR; any read failure gives a 500 with a WARN of ids, never a wider scope; the scope uses no request field.
- **Order and liveness:** guard after the 404 for reads; after the admission row lock or under the clinic IPD advisory lock for writes; the locked check re-reads ward and grant with `clock_timestamp()` and `ADMITTED`; the refusal is fixed text, writes no event, audit or record-access row and logs one INFO line with ids only.
- **Lists:** the in-memory filter runs inside the list's own REPEATABLE READ transaction, ALL callers skip it; the Admitted list filters before any patient, bill or flag lookup; the Safety board, banner, counts, medicine round and change token use the visible set; `otherWardsPastTarget` is a number only; the bed board never reads the patient of an out-of-scope bed.
- **Break-glass and review:** only the token NURSE with a NURSE membership and a narrower-than-ALL scope can open; strict body; one READ COMMITTED transaction with row lock, 409 `already-in-scope`, grant, `bg` event with `grant_id`, record-access row through the patient `api` port and the audit row; database-clock stamps; review by OWNER only, guarded update, 409 for the second owner; opaque length-bounded keyset cursor.
- **Ward assignments and switch:** whole-set PUT under the clinic advisory lock, rows ended and never deleted, active NURSE check through `TeamMemberPort`, `on: true` with a nurse without a ward is 409 every time, `on: false` never refused.
- **Coverage, boundaries, migration, frontend, tests:** all 61 handlers carry exactly one marker and `IpdScopeCoverageTest` checks markers, contract, the 17 by-id endpoints and the refusal tests; only `platform.api` and `patient.api` are used; the migration is forward-only with FORCE RLS and column grants; the frontend uses signals and OnPush, `HttpClient` only in `*.api.ts`, `ScopeRefusals` keeps no state and never locks the page, no hard-coded colours, nothing stored in the browser; no skipped test in the SAH-34 classes; SAH-29 compatibility kept.
