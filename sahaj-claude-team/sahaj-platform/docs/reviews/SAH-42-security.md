# SAH-42 security and privacy review · admin bootstrap registration behind a PIN (dev-tools only)

Reviewer: security-reviewer, read-only. Date: 11 Nov 2026. Done by reading the code, SQL, docs and tests; no Maven, Playwright or build was run. `.env` was not read. Only the SAH-42 files of the mixed tree were judged.

**No Critical or High findings.**
**Verdict: PASS, with one condition.** The server-side gating and the Java code are sound. The database half has never been executed, so it could not be verified and is not passed. **Condition: do not set `SAHAJ_ADMIN_BOOTSTRAP_ENABLED=true` on any machine until the 83 skipped database ITs (plus the 9 other skipped ones) have run green.** Two of those ITs guard the attempt limit itself (see M1).

**The real PIN:** it is not in any file of the working tree (docs, tests, `target*` folders, failsafe reports, binary files); `.env` was not read. It is not in any commit (`git log --all -S` found nothing). The only BCrypt-shaped string in the repository is the placeholder `$2a$12$qqqq...` in `BootstrapEndpointTest.java:60`. Outside the repository it appears in 4 Claude Code transcript files under the user profile, which confirms DEC-034's "treated as known".

## Checked and found sound
- **Dev-only gating (B1-B7):** no bootstrap class or SQL in a normal jar (`DevToolsAbsentFromMainTest`; `PackagedJarDevToolsIT` passed); every bean carries `@ConditionalOnAdminBootstrap`; B6 covers every property that installs Tomcat's `RemoteIpValve`; B7 requires a loopback IP literal; `AdminDevPathFilter` (order -110, ahead of Spring Security) reserves both prefixes with any letter case and the decoded path, uses `anyMatch` over the gates, fails closed; with both dev features on the matchers are disjoint and each gate refuses the other's path; the grants combine safely.
- **Production guard:** byte-identical to `docs/database/ADR-008-guard.sql`; catches the table and any `admin_bootstrap_*` function; the callback refuses to run outside `^sahaj_(dev|test)$`.
- **K1-K6:** JSON body forces a CORS preflight, `OPTIONS` gets 404, `Origin: null` and other origins refused, `Sec-Fetch-Site` must be `same-origin`; DNS rebinding blocked by the `Host` check; forwarding headers can only narrow and appear at most once; the dev proxy keeps `xfwd: true`.
- **PIN handling:** `BCrypt.checkpw(byte[])`; over 64 characters or 72 bytes goes to a dummy hash of the same cost and is counted; the row lock is held through the compare so the count cannot pass 5; no compare while locked; a blank PIN or unreadable body is not counted.
- **Ticket:** 256-bit `SecureRandom`, HMAC with a separate key label, one slot, 5 minutes on the database clock; `register` re-checks the ticket under the advisory lock then the row lock, so a concurrent unlock and register resolves correctly; spent only on CREATED; a repeated cookie counts as missing; cookie `HttpOnly`, `SameSite=Strict`, path `/api/v1/admin/bootstrap`.
- **SECURITY DEFINER functions:** `search_path = pg_catalog, pg_temp`, every name schema-qualified, no dynamic SQL; EXECUTE revoked from PUBLIC and granted to `sahaj_app` only; each refuses when a tenant is bound; SB001-SB003 carry fixed messages; the self-check covers owner, definer, ACL and the temporary CREATE.
- **Logs and errors:** `toString` prints no value on bodies, outcomes, verifier, hasher, gate and exceptions; exceptions have no message or cause (class and SQLSTATE only in the log); the request id is server-made; no request, body or access logging on this chain; audit rows hold no email, PIN, hash or ticket (the admin name is in the CREATED row by design); error bodies are fixed texts and never echo a field name or value.

## Not verified
- **None of the SQL has ever run:** the callback and both callback orders; S4-S26, S30 and every wrong-PIN, lock, ticket and register case over HTTP (83 ITs skipped plus 9); `pg_has_role(...,'set')`; the RETURNS TABLE column `"open"`; two `SET` clauses on one function; `get stacked diagnostics constraint_name`; whether the definer can execute `platform.current_tenant()`; the cleanup and clear-lock runbooks.
- **The `@Transactional` proxy around `BootstrapService` at runtime** (the serialised count depends on it; only a unit test reads the annotation; without the proxy, parallel unlocks each pass `begin` and more than 5 guesses fit in one window). See also code review finding 10.
- K2 (the socket check) is unit-tested only; the hash tool's hidden prompt in a real terminal (plan M-1); the Windows peers in M3 (reasoned, not tested); `npm audit` and `mvn dependency:tree` were not run; `pom.xml` was not diffed for SAH-42; the tree holds unrelated changes from other stories on branch `feature/SAH-39-home-kinetic-background`.

## M1: RESOLVED by design (on reading)
The compare is reached in one place only (`BootstrapService.java:139-146`), after the claim (T1) has committed. Every failure point was walked: claim commit fails or 55P03 (no compare, not counted); connection dies after the claim (counted, one UNJUDGED row at the next `begin` after the lease); compare throws (counted, bodyless 500); judge fails on a wrong or a correct PIN (counted, 500, no ticket); 5th try (count 5, lock and lease in one UPDATE; exactly 5 guesses); BUSY (no compare); lease runs out mid-compare (late judge gets SB004, same answer for right and wrong PIN); concurrent tries (row lock plus single lease); request killed mid-compare (as a dropped connection). More than 5 guesses per window is not possible; the count returns to 0 only on lock expiry, a correct PIN or the clear-lock runbook. The "lifts its own claim's lock" path cannot be abused: lock and live lease coexist only for the 5th claim; a replayed try id gets SB004; the try id is server-made and `sahaj_app` cannot read the state table.

## Other checks
- `@KeepProblemInstance` / `ProblemInstanceScrubber`: no leak; every bootstrap problem goes through `problem()` with a constant path; nothing in main uses the marker (`KeepProblemInstanceNotInMainTest`). `;` and percent-encoded paths seen only in the MockMvc slice; R3-I10 over real HTTP not yet run.
- SQL (read): byte-identical callback copy; five SECURITY DEFINER functions, `search_path = pg_catalog, pg_temp`, no dynamic SQL, `lock_timeout` on the four row-locking ones, EXECUTE to `sahaj_app` only; fixed SQLSTATE texts, SB002 retired; UNJUDGED row holds no email, PIN, hash, ticket, try id or IP; idempotent drops on re-run; guard `^sahaj_(dev|test)$`; runbooks need psql 13 or later.
- Logs and errors: only the wrong-PIN count, one `locked until` line per lock and `adminId=` on CREATED; no PIN, hash, ticket, binding, try id or database message; failed-judge 500 bodyless with `no-store`; 423 and 429 carry Retry-After.
- Gating and production guard: B1-B7, K1-K6 unchanged; `cmp` shows `docs/database/ADR-008-guard.sql` and the main copy IDENTICAL (comments and message wording only changed).
- The real PIN: not searched for (not known to the reviewer). BCrypt-shaped literals in SAH-42 files are placeholders only. Several tests hold 6-digit literals (`BootstrapServiceTest`, `BootstrapPinHashToolTest:20,93`, `BootstrapTransactionProxyTest:192`, `BootstrapRequestChecksIT:149`); rotating the PIN under M2 makes any overlap moot.
