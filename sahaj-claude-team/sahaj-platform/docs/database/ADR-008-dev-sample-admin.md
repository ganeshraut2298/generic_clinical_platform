## What this is, and what it is not

- A **Flyway callback** (`afterMigrate`), not a migration. Nothing is added to `backend/src/main/resources/db/migration/`. No new table, column, index or RLS policy.
- Lives only in the dev-tools source set. The production jar does not contain it, so a production database never receives the grant or the function. Flyway runs it as `sahaj_migrator` after every `migrate`, only when the dev-tools Flyway customizer has added `classpath:db/dev-tools` (conditions C1 to C5 of ADR-008).
- Platform scope. It touches no tenant table and no tenant data, and sets no `app.tenant_id`.
- It changes ADR-003 D1 ("the definer has no INSERT on `platform_admin`") in dev and test databases only, as the human approved (H-DEV-1, W1).

## Prerequisites (human, unchanged)

1. Role `sahaj_admin_definer` exists (`NOLOGIN NOSUPERUSER NOBYPASSRLS NOINHERIT`) and `GRANT sahaj_admin_definer TO sahaj_migrator` (default inherit and set options; the callback checks `member`, `usage` and `set`).
2. The parked admin migrations are active in `db/migration` (renumbered, H-DEV-5). They create the six `platform_admin*` tables, the 13 sign-in functions and the grants this callback builds on.

## Objects the callback creates or changes

| Object | Change |
| --- | --- |
| `platform.platform_admin` | Privilege only: `INSERT (id, email, full_name, password_hash, totp_secret_enc, totp_key_version, totp_enrolled_at)` to `sahaj_admin_definer`. The callback first runs `REVOKE INSERT ... FROM sahaj_admin_definer` so any wider earlier grant disappears, then grants exactly these seven columns. Column names verified against `V2026_11_15_1000`. All other columns (`active` true, `password_changed_at`, `last_sign_in_at`, `totp_last_used_step` null, `created_*`, `updated_*`, `version`) take their defaults. |
| `platform.platform_admin_audit` | Nothing new. Existing grant `SELECT, INSERT` to the definer is enough: the table is append-only through triggers `trg_platform_admin_audit_no_update_delete` and `_no_truncate` (UPDATE, DELETE, TRUNCATE refused for every role), and INSERT is not blocked. The only foreign key from the audit rows used here is `admin_id -> platform_admin(id)`; the admin row is inserted before the audit row in the same statement sequence. |
| `platform.admin_dev_create_sample_admin(...)` | New function, below. |
| Schema `platform` | `CREATE` granted to the definer for `ALTER FUNCTION ... OWNER TO`, taken back at the end of the same script (same pattern as `V2026_11_15_1010`). Self-check fails the run if it stays. |

`sahaj_app` still has no privilege on any `platform_admin*` table. The self-check verifies it.

## The function

```
platform.admin_dev_create_sample_admin(
  p_admin_id         uuid,
  p_password_hash    text,
  p_totp_secret_enc  bytea,
  p_totp_key_version smallint,
  p_ip               inet,
  p_request_id       text)
returns boolean
```

`SECURITY DEFINER`, owner `sahaj_admin_definer`, `SET search_path = pg_catalog, pg_temp` (see decision 1 below), schema-qualified names, no dynamic SQL. `EXECUTE` revoked from `PUBLIC`, granted to `sahaj_app` only.

| Parameter | Type | Rule (else `22023`) |
| --- | --- | --- |
| `p_admin_id` | uuid | not null; generated by Java before encrypting (the GCM associated data binds the ciphertext to this id) |
| `p_password_hash` | text | not null; BCrypt, exactly the table check pattern `^\$2[aby]\$[0-9]{2}\$[./A-Za-z0-9]{53}$` (60 characters) |
| `p_totp_secret_enc` | bytea | not null; 48 to 64 bytes (12-byte nonce + 20-byte secret + 16-byte tag = 48) |
| `p_totp_key_version` | smallint | not null; at least 1 |
| `p_ip` | inet | may be null; stored in the audit row |
| `p_request_id` | text | may be null; at most 100 characters |

Constants inside the function (never parameters): email `sample-admin@example.test`, name `Sample admin`, advisory lock key `202611050008`.

Steps, one transaction (the caller's):

1. `platform.current_tenant()` not null: raise `42501` "admin function in a clinic session".
2. Validate parameters (above). Messages never contain a value.
3. `pg_advisory_xact_lock(202611050008)`.
4. If any row exists in `platform.platform_admin` (active or not, seeded or not): insert audit `AUTH` / `ADMIN_DEV_SAMPLE_REFUSED`, outcome `REFUSED`, refusal code `admin-exists`, no admin id, summary "Sample admin not created: an admin already exists", `ip`, `request_id`. Return **false**.
5. Else insert the admin (already enrolled: secret, key version and `totp_enrolled_at = now()` together, as `ck_platform_admin_totp_all_or_none` requires), insert audit `AUTH` / `ADMIN_DEV_SAMPLE_CREATED`, outcome `APPLIED`, admin id, admin name `Sample admin`, summary "Sample admin created by the dev-only endpoint", `ip`, `request_id`. Return **true**.

The audit rows hold no password, hash, secret, ciphertext, URI or email. No recovery codes are created.

### Return value and errors (for the java-developer)

| Result | Meaning | Java action |
| --- | --- | --- |
| `true` | admin created, audit written | build the 201 response |
| `false` | an admin already exists, REFUSED audit written | answer the empty 404. **Commit the transaction; do not roll back on `false`**, or the REFUSED audit row (ADR-008 test T8) is lost |
| SQLSTATE `42501` | a clinic tenant is bound to the transaction | programming error: 500, never reachable through the endpoint (the dev chain does not bind a tenant) |
| SQLSTATE `22023` | bad parameter (hash format, ciphertext length, key version, null id, request id over 100) | 500 with no detail; the hash and the ciphertext come from the same Java code as the seed, so this signals a bug |
| SQLSTATE `23505` | the unique email already exists. Only reachable if the caller runs at `REPEATABLE READ` or higher (its snapshot predates another committed admin) | treat like `false` for the response (404); use the default `READ COMMITTED` and it does not occur |
| SQLSTATE `22P02` | `app.tenant_id` holds text that is not a uuid | 500 (fail closed) |
| `42501`/`42883`/`3F000` on call | the dev-tools callback has not run (function missing: `42883`) | 500; the startup callback failure normally prevents this |

## Decisions made

1. `search_path = pg_catalog, pg_temp` rather than only `pg_catalog`. The brief said `pg_catalog`; without `pg_temp` listed last, PostgreSQL searches the session's temporary schema first for relations and types, which is the classic SECURITY DEFINER hijack. The ADM-1 functions and their self-check (`search_path=%pg_catalog%pg_temp%`) use the same pair.
2. Database-name guard: the callback refuses to run unless `current_database()` matches exactly `^sahaj_(dev|test)$` (revision 2; revision 1 also accepted `sahaj_dev_staging`, `sahaj_test_prod` and the like, review L1). This is a second layer behind the jar exclusion, so a dev-tools build pointed at any other database fails at startup instead of creating the grant. A developer with a differently named local database must create `sahaj_dev` or `sahaj_test` instead (the `create-database.mjs` script creates exactly those two).
3. The hash pattern is the table's, not "cost 12 only", so a test profile that hashes with a cheaper cost still works. The strength (BCrypt 12) is enforced in Java, as in the seed.
4. `REVOKE INSERT` before `GRANT INSERT (columns)` so the callback converges to exactly the designed state on every run (and removes a table-wide INSERT someone may have added by hand). The table is locked briefly at each dev start; no request depends on that INSERT privilege while Flyway runs, and the whole callback is one transaction.
5. The end-of-script self-check fails the run (and rolls the callback back) if: the definer's INSERT columns are not exactly the seven; `sahaj_app` has any privilege on a `platform_admin*` table; the function is not owned by the definer, not `SECURITY DEFINER`, lacks the fixed `search_path`, or is executable by anyone but the owner and `sahaj_app`; or the definer keeps `CREATE` on schema `platform`.

## Behaviour when the parked migrations are not yet active

The callback exists only in the dev-tools build and only runs once that build is started with the dev-tools customizer active. In that case:

- Admin tables missing: the pre-flight raises "Admin tables are missing: activate the parked admin migrations first (DEC-016)." Flyway fails the `migrate` call and the dev-tools application does not start. Role missing: "Role sahaj_admin_definer does not exist. Create it first (DEC-012, ADR-003 D4 ...)". Wrong membership or role flags: their own messages. Wrong database name: its own message.
- This does **not** break the main migrations: an `afterMigrate` callback runs after the versioned migrations have committed, so they stay applied. The production jar and a plain `mvn spring-boot:run` (without `-Pdev-tools` and the property) never load the callback, so day-to-day work is unaffected.
- Once the prerequisites are done, the next start of the dev-tools build runs the migrations (if any are pending) and then the callback; nothing needs repair.
- Callback order next to `afterMigrate__dev_seed_platform_admin.sql` is alphabetical (`dev_seed` before `dev_tools`). If the env seed is on, the seed admin exists first, the callback still installs the function, and the function then refuses (404 in the API). They do not conflict.
- Request to the owner of `V2026_11_15_1010` (when it is activated and renumbered): its self-check counts functions named `admin\_%` and expects exactly 13. It runs once, before this callback, so a fresh or first-activation database passes. A **later** migration that repeats such a count in a dev database would count `admin_dev_create_sample_admin` too; any such check should exclude `admin\_dev\_%`. The other half of that check (owner, `SECURITY DEFINER`, fixed `search_path`, no `PUBLIC` execute) the new function already satisfies.

## Tenant scope and RLS

None. Platform scope, no `tenant_id`. The six admin tables have no RLS; privileges are the control (ADR-003 D1). The function refuses a call when a tenant is bound, so it can never run inside a clinic session.

## Expected rows and retention

- `platform.platform_admin`: at most **one** row from this function, ever (it refuses while any admin exists). Never deleted; a human switches it off with `active = false` as `sahaj_migrator`.
- `platform.platform_admin_audit`: one `ADMIN_DEV_SAMPLE_CREATED` row, plus one `ADMIN_DEV_SAMPLE_REFUSED` row for each refused call that passes the Java gate (at most 5 per 15 minutes by the rate limiter). Retention 7 years, append-only (ADR-003 D7); these are dev and test rows only.
- No partitioning concern.

## Backward compatibility and clean-up

- Nothing in `db/migration` changes, so the previous app version runs unchanged against any database.
- Switching back to a plain build leaves the function and the column grant in the dev or test database (accepted in ADR-008 "Risks"; the function can still only create the one fixed identity, and only while no admin exists). To remove them: run the runbook `docs/database/runbooks/dev-tools-sample-admin-cleanup.sql` (revision 2, below). `flyway clean` (dev and test only) removes everything.

## Revision 2 (ADR-008 R3): guard callback, cleanup runbook, exact name guard

### 1. Guard callback `docs/database/ADR-008-guard.sql`

Place, unchanged, at `backend/src/main/resources/db/guard/afterMigrate__platform_dev_tools_absent_guard.sql` (main code: shipped in every build, which is the point). Flyway location `classpath:db/guard` is added to `spring.flyway.locations` in `application.yml` (java-developer; customizers that add `db/dev-seed` or `db/dev-tools` must append, not replace).

- Runs as `sahaj_migrator` after every migrate, one `DO` block in Flyway's transaction. Read-only: it never drops, revokes or updates.
- `current_database()` is `sahaj_dev` or `sahaj_test` (exact): returns at once.
- Any other database: raises `P0001` (migrate fails, application does not start) when any of these is true. Each check is skipped when its object does not exist, so the guard passes on a fresh database, on one without the admin tables (the parked migrations are not active today), and on one without the role. `to_regprocedure` and `to_regclass` return null instead of raising when the schema or object is missing.

| # | Finding | Check |
| --- | --- | --- |
| 1 | the dev-only function exists | `to_regprocedure('platform.admin_dev_create_sample_admin(uuid,text,bytea,smallint,inet,text)') is not null` |
| 2 | the definer can INSERT | role `sahaj_admin_definer` exists, table `platform.platform_admin` exists, `has_any_column_privilege('sahaj_admin_definer','platform.platform_admin','INSERT')` (true for a table grant or any column grant) |
| 3 | an active sample admin | table exists and a row has `email = 'sample-admin@example.test'` and `active` |

- Message: `Dev-tools sample admin objects found in database "<name>". Run docs/database/runbooks/dev-tools-sample-admin-cleanup.sql as sahaj_migrator, then start again (ADR-008 R3).` The `DETAIL` lists which of the three findings apply, in words (no email, hash, secret or row value); the `HINT` gives the psql command.
- Platform scope only, no tenant table, no `app.tenant_id`, idempotent (repeatable any number of times, same result).
- Safe by construction when objects are missing: the only static reference to `platform.platform_admin` is inside an `if to_regclass(...) is not null`; PL/pgSQL plans a statement when it first runs, so the unreached statement is never planned.
- After the sample admin is switched off by the runbook, check 3 passes (it looks for an **active** row only), so the application starts again.
- Not chosen (as ADR-008 R3): a versioned or repeatable migration (runs once, or reruns only on a checksum change), or a check in `validate db`.
- The function is matched by its exact signature, as specified. A function of the same name with other parameters would not be found; none is planned.

### 2. Cleanup runbook `docs/database/runbooks/dev-tools-sample-admin-cleanup.sql`

Stays under `docs/database/runbooks/` (not copied into `backend/`; it is not run by Flyway). Run by a human:

```
psql -v ON_ERROR_STOP=1 -U sahaj_migrator -d <database> -f docs/database/runbooks/dev-tools-sample-admin-cleanup.sql
```

The file stops at once (`\quit`) if `ON_ERROR_STOP` was not set (psql 13 or later, `:{?name}` test). One `begin; ... commit;`; an error rolls everything back.

| Step | Effect | Skipped when |
| --- | --- | --- |
| 0 | Pre-flight: current user may drop the function (usage of its owner role) and change the table (usage of the table owner); else a clear message | nothing to check |
| 1 | `drop function if exists platform.admin_dev_create_sample_admin(...)` | function or schema missing (a notice) |
| 2 | `revoke insert on platform.platform_admin from sahaj_admin_definer` (also removes column-level grants) | role or table missing |
| 3 | Outside `sahaj_dev` / `sahaj_test` only: `platform_admin.active = false` (+ `updated_at`, `version`) for `sample-admin@example.test` if active; `platform_admin_session` rows of that admin with `revoked_at is null` get `revoked_at = now()`, `revoked_reason = 'ADMIN_OFF'`; open `platform_admin_preauth` rows get `consumed_at = now()`; one `platform_admin_audit` row (kind `ACTION`, action `ADMIN_DEV_SAMPLE_DEACTIVATED`, admin id and name, summary "Sample admin switched off by the dev-tools cleanup script", outcome `APPLIED`, no ip, no request id) | database is dev/test (admin left alone), table missing, or no active sample admin (so a second run writes no second audit row) |
| 4 | Self-check, raises and rolls back if: the function exists; the definer still has any INSERT on the table; outside dev/test an active sample admin remains | nothing |

Real columns used (from `V2026_11_15_1000`): `platform_admin(id, email, full_name, active, updated_at, version)`; `platform_admin_session(admin_id, revoked_at, revoked_reason)` where `revoked_reason in ('SIGN_OUT','REUSE','ADMIN_OFF','EXPIRED')` and `(revoked_at is null) = (revoked_reason is null)`; `platform_admin_preauth(admin_id, consumed_at)`; `platform_admin_audit(kind, action, admin_id, admin_name, summary, outcome)`.

**New audit action code: `ADMIN_DEV_SAMPLE_DEACTIVATED`.** `platform_admin_audit.action` is free text (1 to 60 characters, `ck_platform_admin_audit_action` has no list), so **no migration change** is needed. Anyone who keeps a list or labels of audit actions in Java or the Angular Audit log page (ADM-3) must add this code (and `ADMIN_DEV_SAMPLE_CREATED` / `ADMIN_DEV_SAMPLE_REFUSED` from revision 1), or show unknown codes as plain text.

Never deletes any row (retention: admin rows kept; audit 7 years, append-only). Does not touch other admins, other roles, other privileges or tenant data. Idempotent: the second run finds nothing to do, writes nothing, and the self-check passes. In `sahaj_dev` it may be run after each use; the next dev-tools start recreates the function and the grant. If another role granted INSERT to the definer, a revoke by `sahaj_migrator` does not remove it; the self-check then fails with a clear message.

**Review by reading.** None of the three SQL files could be run: the admin tables and the role `sahaj_admin_definer` exist in no database (the migrations are parked), so every statement above is unexecuted.
