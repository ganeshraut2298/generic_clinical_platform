## Masters: `opd.emr_complaint`, `opd.emr_investigation`, `opd.emr_advice` (global, no RLS, SELECT only for `sahaj_app`)
Same kind as `opd.medicine` and `opd.diagnosis`. `sahaj_app` has no insert, update, delete or truncate (42501). Nothing is granted to PUBLIC.

| Column | Type | Null | Default | Rule |
| --- | --- | --- | --- | --- |
| `id` | uuid | no | `gen_random_uuid()` | primary key; the seed sets `md5('opd.<table>:' \|\| lower(name))::uuid`, so every environment has the same id |
| `name` | text | no | | `ck_<table>_name`: 1 to 200 characters after trim |
| `name_mr`, `name_hi` | text | yes | | **`emr_advice` only** (ADR-020 D13): null or 1 to 200 characters; null in the seed (no translation is drawn) |
| `specialty_hint` | text | yes | | `ck_<table>_specialty_hint`: null or one of the 15 starter department keys (gm, dental, og, paeds, physio, ortho, eye, ent, derm, diab, cardio, ayush, onco, surgery, psych). Ordering hint only. **Changed from gp/dental/paeds/homeo (ADR-020 D13)** |
| `sort_order` | integer | no | 0 | `>= 0`; seeded ten apart |
| `created_at` | timestamptz | no | `now()` | |

Indexes: `uq_<table>_name_lower (lower(name) text_pattern_ops)` unique: refuses a repeated name ignoring case and serves the prefix search `where lower(name) like lower(:q) || '%' escape '\'`. Master order: `order by (specialty_hint is distinct from :specialty), sort_order, lower(name)`; the lists are a few hundred rows, so the unique index is the only one (as for `opd.medicine`).

Seed (`..._1010`): complaints 59, investigations 46 (the first 13 are the mockup Investigation master in the mockup order, the 14th is the mockup's organisation example "Thyroid profile (T3, T4, TSH)"), advice 50 (the first 14 are the advice lines of the mockup case paper presets). Hints: null (general), dental or paeds; the three homeopathy complaints (Recurrent colds, Hair fall, Allergy that keeps coming back) were hint `homeo` and are now null. No row used `gp`. All three tables carry the comment "Starter list, not clinically reviewed".

## Usage: `opd.emr_item_usage` (clinic table, RLS)
`tenant_id` default `platform.current_tenant()` with FK to `platform.tenant`, ENABLE + FORCE RLS, policy `p_emr_item_usage_tenant` for `sahaj_app`.

| Column | Rule |
| --- | --- |
| `doctor_membership_id uuid` | no foreign key (cross-module) |
| `master` | complaints, diagnoses, medicines, investigations, advice |
| `item_key` | 1 to 40; `ck_emr_item_usage_item_key_shape`: ICD-10 code for diagnoses, lower-case uuid text for the other four, so typed text cannot be stored |
| `use_count integer` | `>= 1`, default 1 |
| `last_used_at timestamptz` | not null |
| `created_at`, `updated_at` | no `created_by`: the recorder has no user argument |

PK `(tenant_id, doctor_membership_id, master, item_key)` serves the upsert. `ix_emr_item_usage_ranking (tenant_id, doctor_membership_id, master, use_count desc, last_used_at desc)` serves the ranked read for one doctor and one master. Grants: select, insert, update; no delete. About 300 to 1,000 rows per clinic a year, 3 to 10 million after a year for 10,000 clinics; no partitioning, review at 30 million. Never hard-deleted, not a clinical record (no patient data).

Upsert: `insert into opd.emr_item_usage (doctor_membership_id, master, item_key, last_used_at) values (...) on conflict (tenant_id, doctor_membership_id, master, item_key) do update set use_count = opd.emr_item_usage.use_count + 1, last_used_at = greatest(opd.emr_item_usage.last_used_at, excluded.last_used_at), updated_at = now()`. The column default fills `tenant_id` before the conflict check. A uuid `item_key` must be the lower-case text of the uuid (`UUID.toString()`).

## Test cases for QA that still apply (S-numbers kept)
- S-01 After Flyway: complaints 59, investigations 46, advice 50.
- S-02 `sahaj_app` can select the three masters without a bound tenant; insert, update, delete, truncate refused (42501); PUBLIC has no grant.
- S-03 None of the three masters has a `tenant_id` column.
- S-04 Duplicate name ignoring case in each master refused (23505); the same name in two masters allowed.
- S-05 Name of 0 characters, only spaces, 201 characters refused (23514); 200 allowed. `specialty_hint` 'gp', 'homeo', 'ayur' refused (changed: the 15 starter keys and null are accepted). `sort_order` -1 refused.
- S-06 Prefix search `lower(name) like 'cou%'` returns Cough rows; `%`, `_`, `\` typed as `q` match literally when escaped.
- S-07 The 13 mockup investigations are present with the exact names (Complete blood count (CBC), ESR, Random blood sugar, HbA1c, Lipid profile, Liver function test, Kidney function test, TSH, Dengue NS1, Widal, Urine routine, X-ray chest PA, ECG).
- S-08 Ids are stable: `id = md5('opd.emr_complaint:' || lower(name))::uuid` for every seeded row (matching table name).
- S-09 The comment on each master contains "Starter list, not clinically reviewed".
- S-20 `opd.diagnosis` still has 53 rows, `opd.medicine` 52, `platform.specialty_template` unchanged.
- S-36 Usage: `use_count` 0 refused; `master` 'allergies' refused; `item_key` of 41 characters, empty, free text ('Fever'), an upper-case uuid or a malformed ICD-10 refused; a lower-case uuid accepted for complaints, investigations, advice and medicines; 'J06.9' and 'R50.9' accepted for diagnoses but a uuid refused for diagnoses.
- S-37 Usage upsert: two inserts of one key with `on conflict ... do update` give `use_count` 2; `last_used_at` keeps the later time; two concurrent upserts both count; another doctor has its own row; `delete` refused (42501).
- S-38 Ranking read for one doctor and one master returns `use_count desc, last_used_at desc` and uses `ix_emr_item_usage_ranking`.
- S-40 The application starts on the new schema and the SAH-7 and IPD tests still pass.
- New: `emr_advice.name_mr` and `name_hi` are null for all 50 rows; 0 and 201 characters refused; the three former homeopathy complaints have `specialty_hint` null.
