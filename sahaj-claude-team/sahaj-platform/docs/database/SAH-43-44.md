## Global tables (no tenant column, no RLS, SELECT only for `sahaj_app`, changed by migration only)
Same kind as `opd.medicine` and `opd.diagnosis`. `sahaj_app` has no insert, update, delete or truncate (42501). Nothing is granted to PUBLIC.

### `opd.emr_complaint`, `opd.emr_investigation`, `opd.emr_advice` (same shape)
| Column | Type | Null | Default | Rule |
| --- | --- | --- | --- | --- |
| `id` | uuid | no | `gen_random_uuid()` | primary key; the seed sets `md5('opd.<table>:' \|\| lower(name))::uuid`, so every environment has the same id |
| `name` | text | no | | `ck_<table>_name`: 1 to 200 characters after trim |
| `specialty_hint` | text | yes | | `ck_<table>_specialty_hint`: null, gp, dental, paeds, homeo. Ordering hint only |
| `sort_order` | integer | no | 0 | `ck_<table>_sort_order` >= 0; seeded ten apart |
| `created_at` | timestamptz | no | `now()` | |

Indexes: `uq_<table>_name_lower (lower(name) text_pattern_ops)` unique. It refuses a repeated name ignoring case and serves the prefix search `where lower(name) like lower(:q) || '%' escape '\'`. Master order (D3): `order by (specialty_hint is distinct from :specialty), sort_order, lower(name)`; the lists are a few hundred rows at most, so no further index is needed (the unique index is the only one, as for `opd.medicine`).

### `opd.emr_template`
`template_key` text (`ck_emr_template_key`: gp, dental, paeds, homeo), `version` integer >= 1, `name` 1 to 80, `created_at`. PK `pk_emr_template (template_key, version)`. "Newest version" = `max(version)` per key (served by the PK).

### `opd.emr_template_section`
| Column | Rule |
| --- | --- |
| `template_key`, `version` | FK `fk_emr_template_section_template` to `emr_template` |
| `section_key` | `^[a-z][a-z0-9_]{1,39}$` |
| `position` | integer >= 1; `uq_emr_template_section_position (template_key, version, position)` |
| `label` | 1 to 60 |
| `part` | ASSESSMENT or TREATMENT |
| `required_default`, `hideable` | boolean, not null; defaults false and true |
| `editor_type` | the 11 values of FR-11: COMPLAINTS, VITALS_STEPPERS, SIGNS, SYSTEMS, DIAGNOSIS, PRESCRIPTION, TOOTH_CHART, TREATMENT_PLAN, SERVICES, ADVICE, CHIP_LIST |
| `icon_key` | null or `^[a-z][a-z0-9_-]{0,39}$`; null everywhere (OQ-43-20) |
| `options_source` | MASTER, TEMPLATE, TARIFF, NONE |
| `options_master` | null or complaints, diagnoses, medicines, investigations, advice; `ck_emr_template_section_master_iff_source`: set exactly when the source is MASTER |

PK `pk_emr_template_section (template_key, version, section_key)`: unique section keys within a version, and the read "all sections of one version" `order by position`.

### `opd.emr_template_option`
PK `(template_key, version, section_key, option_key)`, FK `fk_emr_template_option_section` to the section, `uq_emr_template_option_position` on `(template_key, version, section_key, position)`, `option_key` `^[a-z][a-z0-9_]{0,39}$`, `label` 1 to 80, `style` NORMAL or ALERT (red chip), `is_none` boolean. `uq_emr_template_option_one_none` (partial, where `is_none`): at most one None option per section. "At least one option in every TEMPLATE section" is not a constraint (ADR); it is test S-30.

### `opd.emr_specialty_alias`
PK `alias_normalised` text, 1 to 80, and the check that it equals `lower(btrim(regexp_replace(x, '\s+', ' ', 'g')))`, so only the normalised form can be stored and the lookup is an exact primary-key match. `template_key` (4 values). Not immutable (the product owner adds aliases by migration; a wrong alias may be fixed by a later migration).

### Immutability trigger (D4)
`opd.deny_emr_template_change()` raises SQLSTATE 42501 with a message containing "is immutable". `BEFORE UPDATE OR DELETE ... FOR EACH ROW` and `BEFORE TRUNCATE ... FOR EACH STATEMENT` on `emr_template`, `emr_template_section`, `emr_template_option`. It applies to every role, including the owner `sahaj_migrator`. INSERT stays open: a new version is new rows. (Flyway clean drops the tables, which does not fire triggers, so the test database reset still works.)

## Clinic tables (RLS)
All four: `tenant_id uuid not null default platform.current_tenant()` with FK to `platform.tenant` (the application never writes it), `ENABLE` + `FORCE ROW LEVEL SECURITY`, policy `p_<table>_tenant for all to sahaj_app using (tenant_id = platform.current_tenant()) with check (...)`, grants revoked from sahaj_app and PUBLIC then given as below. No foreign key to `platform.membership` or to any global EMR table.

| Table | Columns | Keys, constraints | Index (query served) | Grants |
| --- | --- | --- | --- | --- |
| `opd.emr_template_setup` | `template_key`, `revision bigint` default 0 (>= 0), `created_at`, `created_by` not null, `updated_at`, `updated_by` | PK `(tenant_id, template_key)`; key in 4 values. A first change by two owners at once collides on the PK (the app answers 409) | the PK serves the read of the revision | select, insert, update |
| `opd.emr_template_override` | `template_key`, `section_key`, `shown`, `required`, `created_at`, `created_by` not null, `updated_at`, `updated_by` | PK `(tenant_id, template_key, section_key)`; `ck_emr_template_override_hidden_not_required`: `shown or not required`; key patterns as the global tables; no FK to the global section | the PK serves "all overrides of this clinic and template" (leading columns) and the single-row upsert | select, insert, update, delete |
| `opd.emr_settings` | `section_panel` COLLAPSED/OPEN default COLLAPSED, `right_panel_first` CASE_PAPER/PAST_VISITS default CASE_PAPER, `default_part` default ASSESSMENT with `ck_emr_settings_default_part (default_part = 'ASSESSMENT')`, audit columns (`created_by` not null), `version bigint` default 0 | PK `tenant_id` (one row per clinic) | the PK | select, insert, update |
| `opd.emr_item_usage` | `doctor_membership_id uuid`, `master` (5 values), `item_key` 1 to 40, `use_count integer` >= 1 default 1, `last_used_at timestamptz` not null, `created_at`, `updated_at` | PK `(tenant_id, doctor_membership_id, master, item_key)` serves the upsert; `ck_emr_item_usage_item_key_shape`: for `diagnoses` an ICD-10 code (same pattern as `opd.diagnosis.code`), for the other four a lower-case uuid text | `ix_emr_item_usage_ranking (tenant_id, doctor_membership_id, master, use_count desc, last_used_at desc)` serves the ranked read for one doctor and one master | select, insert, update; no delete |

Notes for the developer:
- `created_by` is `not null` on setup, override and settings: write the signed-in user's id. `emr_item_usage` has no `created_by` / `updated_by`: the recorder has no user argument and the doctor is `doctor_membership_id`.
- Override and setup are separate tables with no foreign key: the application must change the override and increment `revision` in one transaction (ADR-019 D5). The database does not link them.
- Settings: lazy row. The first save inserts at `version = 0`; a stale `version` is a 409 in the application.
- Usage upsert: `insert into opd.emr_item_usage (doctor_membership_id, master, item_key, last_used_at) values (...) on conflict (tenant_id, doctor_membership_id, master, item_key) do update set use_count = opd.emr_item_usage.use_count + 1, last_used_at = greatest(opd.emr_item_usage.last_used_at, excluded.last_used_at), updated_at = now()`. The column default fills `tenant_id` before the conflict check, so the insert does not have to list it. Row level security still applies to the update branch (a row of another clinic is never matched).
- A uuid `item_key` must be the lower-case text of the uuid (`UUID.toString()`); an upper-case or typed value is refused by the check (23514).

## Tenant scope and RLS
Global tables: no tenant. Clinic tables: row level security as above, so clinic A never sees or changes clinic B's overrides, revisions, settings or usage; with no tenant bound `platform.current_tenant()` is null and nothing is visible or insertable (fails closed). `sahaj_app` cannot bypass RLS.

## Expected rows
| Table | Rows |
| --- | --- |
| Masters, templates, sections, options, aliases | 59 + 46 + 50, 4, 38, 45, 8 in total; grows by migration only |
| `emr_template_setup` | at most 4 per clinic (one per template ever changed): 10,000 clinics gives at most 40,000 |
| `emr_template_override` | at most 38 per clinic (every section overridden), expected under 10: at most 380,000 for 10,000 clinics |
| `emr_settings` | at most 1 per clinic: 10,000 |
| `emr_item_usage` | doctors x distinct items used. A doctor uses perhaps 100 to 300 distinct items across the five masters in a year, and 1 to 3 doctors per clinic: about 300 to 1,000 rows per clinic per year, so roughly 3 to 10 million rows for 10,000 clinics after one year, growing slowly because items repeat. Under the 50 million threshold: no partitioning planned. Review at 30 million |

## Retention
Masters, templates and aliases: kept for ever (template versions are never deleted). Overrides: until the owner resets (a reset deletes rows; `platform.audit_event` keeps the before and after). Setup revision and settings: life of the clinic. Usage: life of the clinic in phase 1; no patient data in it, so it is not a clinical record. Never hard-deleted by the application (no DELETE grant on usage; overrides are setup data, not clinical).

## Backward compatibility
Purely additive: new tables, indexes, a function and triggers. The previous application version does not know them and runs unchanged against the new schema. Rolling forward needs no data change. To remove a table later use expand and contract over two releases.

## Questions for the human or a clinician (data I kept out)
1. **Chip content.** The BRD and mockup name no chips for: Local examination, Extra-oral and Intra-oral examination, Radiographs, Birth and immunisation history, Development, Vaccines given today, Case history, Mentals and generals. They carry only their None option. Dental Medical alerts has only what the mockup names (penicillin, NSAIDs, latex, hypertension, type 2 diabetes); typical dental alerts such as bleeding disorders, heart conditions or blood thinners are not in the mockup and were not added. A clinician writes these (OQ-43-8).
2. **None option beyond OQ-43-19.** OQ-43-19 asks for it in the four required chip lists. I added one to every TEMPLATE chip list (History & allergies, Local, Extra-oral, Radiographs, Birth, Development, Vaccines), because an owner can switch Required on for any shown section and the doctor could then never complete it with no finding. Remove by a new template version if not wanted.
3. **Dental treatment plan options.** The story table says "T (suggestion rules in SAH-49)", but a plan is not a chip list, so `options_source = NONE` (a TEMPLATE source needs at least one chip). SAH-49 may need a source of its own, as a new template version.
4. **Paediatrics General examination signs.** Reuses the same seven signs as General practice (FR-11 describes one Signs editor); the BRD gives no separate list.
5. **Not hideable prescription in Dental and Paediatrics.** ADR D4 says `prescription` is not hideable, so Dental's optional Prescription and Paediatrics' optional "Prescription (by weight)" also cannot be hidden. Say if only the General practice one should be fixed.
6. **Paediatrics and Homeopathy have no allergy section** (OQ-43-14, patient safety, built as the BRD table says, already flagged in DEC-038).
7. **Section keys** are the BA's reading (SO-44-10) and become permanent when SAH-46 stores snapshots.
8. **Existing test needs an allow-list entry (QA).** `RowLevelSecurityCatalogIT.noTableOutsideTheDocumentedExceptionsIsWithoutRowLevelSecurity` fails for any table without enabled and forced RLS unless it is in `NO_RLS_BY_DESIGN`. The seven new global tables follow ADR-019 D2 (no RLS, like `opd.medicine`), so QA must add: `opd.emr_complaint`, `opd.emr_investigation`, `opd.emr_advice`, `opd.emr_template`, `opd.emr_template_section`, `opd.emr_template_option`, `opd.emr_specialty_alias`. (The other option, RLS with a `using (true)` policy as SAH-31 did for `ipd.drug`, would break the policy test instead and was not chosen: ADR-019 says no RLS.)

## Test cases for QA (S-numbers)
Run as `sahaj_app` with a bound tenant unless stated; use two clinics for the isolation cases.

Global tables
- S-01 After Flyway, counts: complaints 59, investigations 46, advice 50, templates 4, sections 38, options 45, aliases 8.
- S-02 `sahaj_app` can select all seven global tables without a bound tenant and gets rows; insert, update, delete, truncate on each is refused 42501 (also column-level: no INSERT or UPDATE column privilege); PUBLIC has no grant.
- S-03 None of the seven tables has a column named `tenant_id`.
- S-04 Duplicate name ignoring case in each master is refused (23505), for example 'fever' after 'Fever'; the same name in two different masters is allowed.
- S-05 Name of 0 characters, only spaces, and 201 characters is refused (23514); 200 allowed. `specialty_hint` 'ayur' refused; null, gp, dental, paeds, homeo accepted. `sort_order` -1 refused.
- S-06 Prefix search `lower(name) like 'cou%'` returns Cough rows; `%`, `_` and `\` typed as `q` match literally when escaped with `escape '\'`.
- S-07 The 13 mockup investigations are present with the exact names (Complete blood count (CBC), ESR, Random blood sugar, HbA1c, Lipid profile, Liver function test, Kidney function test, TSH, Dengue NS1, Widal, Urine routine, X-ray chest PA, ECG).
- S-08 Ids are stable: `id = md5('opd.emr_complaint:' || lower(name))::uuid` for every seeded row of the three masters (with the matching table name).
- S-09 The master comment on each of the 7 tables contains "Starter list, not clinically reviewed".
- S-10 Template counts: gp 11 sections and 6 required, dental 11 and 7, paeds 9 and 4, homeo 7 and 6; total 38; all version 1; template names General practice, Dental, Paediatrics, Homeopathy.
- S-11 Section order: positions 1..n without gaps per template; parts follow the story table (Assessment 6/6/5/4, Treatment 5/5/4/3); section keys and labels equal the story table (compare each row).
- S-12 `hideable = false` exactly for gp history_allergies, gp prescription, dental medical_alerts, dental prescription, paeds prescription, homeo remedy_potency; all other 32 are hideable.
- S-13 Editor types: only the 11 allowed values; inserting 'FREE_TEXT' is refused (23514, as migrator). Part 'OTHER' refused. `options_source` 'X' refused. `options_master` set with source TEMPLATE refused, and source MASTER with a null master refused; options_master 'allergies' refused.
- S-14 Duplicate section key in one version refused (23505); duplicate position in one version refused; section key 'Bad-Key' or 'a' (1 char) refused; label of 61 characters refused.
- S-15 A section whose template version does not exist is refused (23503). An option whose section does not exist is refused (23503).
- S-16 Immutability: as `sahaj_migrator` (owner), `update`, `delete` and `truncate` on `emr_template`, `emr_template_section`, `emr_template_option` are each refused with 42501 and a message containing "immutable"; the rows are unchanged. An insert of a new version 2 (template, one section, one option) works inside a rolled-back transaction, and after it "newest version per key" is 2 while version 1 rows are unchanged.
- S-17 Every section with `options_source = 'TEMPLATE'` has at least one option row (a test, not a constraint); every `CHIP_LIST` section with `required_default` has exactly one option with `is_none` (dental medical_alerts, dental intra_oral_exam, homeo case_history, homeo mentals_generals); a second `is_none` option in one section is refused (23505).
- S-18 gp general_exam has the seven signs in order (pallor, icterus, cyanosis, clubbing, lymph_nodes, oedema, dehydration); gp systemic_exam has cvs, rs, cns, abdomen; gp history_allergies allergy chips have style ALERT; option style 'RED' refused.
- S-19 Specialty aliases: the 8 rows map as in ADR D6; an alias with capitals ('Dental'), a leading space, or a double space is refused (23514); template_key 'ayur' refused; a duplicate alias is refused (23505).
- S-20 The other opd tables are unchanged: `opd.diagnosis` still has 53 rows, `opd.medicine` 52, `platform.specialty_template` unchanged.
- S-21 Specialties with no template (ayur, physio, derma, gynae, ent, oncology, surgery) have no row in `emr_template` and no alias.

Clinic tables
- S-30 Each of the four tables has RLS enabled and forced and exactly one policy for sahaj_app on `platform.current_tenant()` (the existing catalog test covers it once the tables exist). Grants: setup, settings and usage select/insert/update; override select/insert/update/delete; no TRUNCATE, no DELETE on setup, settings and usage.
- S-31 With no bound tenant: select returns zero rows, insert is refused (RLS). With clinic A bound, inserting a row with clinic B's tenant_id is refused. Clinic B cannot read, update or delete A's rows (zero rows affected) in all four tables.
- S-32 Override: `shown=false, required=true` refused (23514, `ck_emr_template_override_hidden_not_required`); `shown=false, required=false`, `shown=true, required=true` and `shown=true, required=false` accepted. Duplicate (clinic, template, section) refused (23505). Template key 'ayur' and section key 'Bad Key' refused. Delete works (reset). `created_by` null refused (23502).
- S-33 Override survives a template version: an override for a section key that exists in no version is accepted (no foreign key).
- S-34 Setup: `(tenant, template)` is unique; two concurrent first inserts: one succeeds and one gets 23505. `revision` -1 refused; update to revision + 1 works.
- S-35 Settings: defaults on a minimal insert are COLLAPSED, CASE_PAPER, ASSESSMENT, version 0; `section_panel` 'HALF' refused; `right_panel_first` 'TOP' refused; `default_part` 'TREATMENT' refused; a second row for the same clinic refused (23505); version -1 refused.
- S-36 Usage: `use_count` 0 refused; `master` 'allergies' refused; `item_key` of 41 characters, empty, free text ('Fever'), an upper-case uuid or a malformed ICD-10 refused; a lower-case uuid accepted for complaints, investigations, advice and medicines; 'J06.9' and 'R50.9' accepted for diagnoses but a uuid refused for diagnoses.
- S-37 Usage upsert: two inserts of the same key with `on conflict ... do update set use_count = use_count + 1` give use_count 2; `last_used_at` keeps the later of the two times (greatest); two concurrent upserts both count (final 2). Another doctor in the same clinic has its own row. `delete` on usage is refused (42501).
- S-38 Ranking read for one doctor and one master returns used items by `use_count desc, last_used_at desc` and uses `ix_emr_item_usage_ranking` (QueryPlansIT style, with enough rows or `enable_seqscan` off).
- S-39 No column in the four tables can hold a patient id, visit id or free text beyond the keyed fields (review of the column list: no such column exists).
- S-40 The application can start on the new schema and the SAH-7 and IPD tests still pass (backward compatibility).
