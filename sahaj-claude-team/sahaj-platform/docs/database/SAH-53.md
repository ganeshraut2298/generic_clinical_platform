### How the mockup became rows (decisions the BA/architect/human may want to check)
1. **Hide locks as data:** Allergies everywhere (`emr_section.always_shown`), PCPNDT Form F in `og` (`emr_starter_department_section.always_shown`). Dropping the PCPNDT lock is one `update` row in a new migration plus a new starter layout version (the layout stores `hideLocked`).
2. **Physiotherapy / Prescription (Rx): `shown = false`, `required = false`.** The mockup switches Rx off in Physiotherapy and still counts it required (`REQ` has `rx`), which breaks the rule "a hidden section is never required" (SAH-53-2, check `shown or not required`). This is the only departure from the mockup's computed values. The story criterion "Required at start (12 keys)" is still true as a list of keys; the Required count of physio is one lower than a literal reading.
3. **Consent forms:** shown only for the six departments with the consent flag (dental, og, ortho, derm, onco, surgery); hidden in the other nine (gm, paeds, physio, eye, ent, diab, cardio, ayush, psych), as the mockup logic says.
4. **Field keys:** the label in lower case, runs of other characters made one underscore (`BP systolic` -> `bp_systolic`, `Dose & frequency` -> `dose_frequency`, `Sets × reps` -> `sets_reps`). No collisions inside a section. Section keys are the mockup `S` keys unchanged.
5. **Options:** only a *complete* list in the mockup hint becomes options (`Mild / Moderate / Severe`, `DM, HTN, TB, Thyroid, Asthma`). A hint that ends with an ellipsis (`Shoulder, knee, hip, spine…`, `None, aspirin, clopidogrel…`), names a source (`By region`, `Vendor list`, `Per eye`, `Saved clinic templates`) is not a list: no options, `allow_free_text = true` (ADR-020 D3). Ranges with members are spelled out: Grade 0-3 (perio mobility), Oxford 0-5 (MMT grade), ECOG 0-4 (labels "0".."4", the descriptions are not drawn), ASA I-IV, histology Grade 1/2/3; "Before / after food" -> Before food, After food; "Class I / II / III" -> Class I, II, III. A label that starts with a digit gets the key prefix `o` (`o0`, `o100`).
6. **None option (SAH-53-1):** added to the required multi-select and checklist fields that have options: `modalities.modality`, `sx_fitness.pre_op_tests` (2 rows, `is_none`, key `none`, last position). **Exceptions, required choice fields with options and no None** (a scale, a setting, a chosen plan item or the outcome of an assessment): `dental_chart.numbering`, `pain.scale`, `mmt.grade`, `onc_ecog.ecog`, `onc_regimen.dose_level`, `sx_fitness.asa_grade`, `sx_fitness.pac`, `sx_plan.anaesthesia`. Required choice fields whose hint is not a complete list have no options, so they accept free text: `rom.joint`, `rom.movement`, `mmt.muscle_group`, `va.distance_va`, `lesion_map.morphology`, `sx_fitness.blood_thinners`, `sx_consent.consent_items`. Question for the architect/BA: the criterion says every required choice field "that offers a fixed choice list" has a None; this is the narrow reading above.
7. **Option source mapping:** Complaint -> complaints; Provisional and Final diagnosis -> diagnoses; Lab tests, Radiology -> investigations; Drug -> medicines (ADR-020 D3); the four search lists named Procedure -> SERVICES (`procedures`, `tx_plan`, `dental_done`, `sx_plan`). **My addition, please confirm:** the `Advice` chips field of the `advice` section -> MASTER `advice` (ADR-020 names only search lists, but the advice master exists for it). Other search lists (Drug allergy, Test, Primary site, Histology) are free typed. `allow_free_text` is true for every search list and every choice field without options.
8. **Tables:** four TABLE fields have columns because their hint lists them (Surgical history: Procedure, Year; Results: Value, Unit, Reference range; Previous deliveries: Year, Mode, Outcome, Baby weight; Immunization Given: Vaccine, Date, Batch no.). Other tables (`Sph / Cyl / Axis` with `RE / LE`, `Probing depth`, `Lab values`) have null columns (one column "entry").
9. **Dentition** (`Toggle`, hint "Adult 32 / Child 20 / Mixed") is kept as the mockup draws it, a TOGGLE with no options.
10. **Layout document stored by the database** (starter layout; the app writes department versions in the same shape): `{"schemaVersion":1,"sections":[{key, source:"LIBRARY", name, kind, description, part, position, shown, required, print, copy, collapsed, whoCanFill:[DOCTOR|NURSE|RECEPTION], hideLocked, fields:[{key,label,type,meta,required,optionsSource,master,allowFreeText,options:[{key,label,isNone}],columns,min,max}]}]}`. `valueKind` and `hideLockReason` are not stored: the application derives them (valueKind is fixed by type in code; the reason text is a UI string). `hideLocked` = section lock or placement lock. The draft (`emr_department.draft_layout`) holds `{"schemaVersion":1,"sections":[{key,part,shown,required,print,copy,collapsed,whoCanFill}]}` only.

### `opd.emr_record`
Columns: `id`, `encounter_type` OPD_VISIT/IPD_ROUND/ER_ASSESSMENT, `opd_visit_id`, `ipd_admission_id`, `round_date date`, `er_case_id`, `patient_id`, `opened_by_membership_id` not null, `department_key`, `department_name` 1-60, `starter_key` null (15), `layout_kind` DEPARTMENT_VERSION/STARTER_LAYOUT, `department_version_id`, `starter_layout_version`, `choice_source` DOCTOR_SPECIALTY/DOCTOR_DEPARTMENT/CLINIC_DEFAULT/SWITCHED, `status` DRAFT/SIGNED default DRAFT, `signed_at`, `signed_by`, `sections jsonb` not null default `{}` (object, <= 1 MB), `schema_version smallint` default 1, `ui_part` null/ASSESSMENT/TREATMENT, `ui_section_key`, `admission_advised` default false, `referral_line` null or 1-300, `revision bigint` default 0, `created_at` (partition key) default now(), `created_by` not null, `updated_at`, `updated_by`.
Checks: exactly the ids of the encounter type (`ck_emr_record_encounter_ids`: OPD visit id only; IPD admission id + round date only; ER case id only; patient required except for ER); layout reference matches the kind (`ck_emr_record_layout_ref`: version id for DEPARTMENT_VERSION; starter layout version and starter key for STARTER_LAYOUT); `(status = 'SIGNED') = (signed_at is not null)` and signed_at/signed_by both set or both null; referral line only when admission is advised.
Keys to other tables: `(tenant_id, patient_id)` -> `patient.patient (tenant_id, id)`; `(tenant_id, opd_visit_id)` -> `opd.visit (tenant_id, id)` (added in the 9 Dec file); `(tenant_id, department_version_id)` -> `emr_department_version (tenant_id, id)`; `(starter_key, starter_layout_version)` -> `emr_starter_layout`. Null columns skip the key.
Indexes (partitioned, local to each partition) and the query each serves:
- `ix_emr_record_tenant_visit (tenant_id, opd_visit_id) where opd_visit_id is not null`: find-or-insert of the OPD open; the Queue card's `emrRecordId`/`emrStatus`.
- `ix_emr_record_tenant_admission_round (tenant_id, ipd_admission_id, round_date) where ipd_admission_id is not null`: IPD round find-or-insert.
- `ix_emr_record_tenant_er_case (tenant_id, er_case_id) where er_case_id is not null`: Emergency find-or-insert.
- `ix_emr_record_tenant_patient_signed (tenant_id, patient_id, department_key, signed_at desc) where status = 'SIGNED'`: Copy from last visit (SAH-51, later), Past visits.
- `ix_emr_record_tenant_patient_created (tenant_id, patient_id, created_at desc) where patient_id is not null`: last visit date, visit count, Past visits.
Partitions: `opd.emr_record_YYYY_MM` for Nov 2026 to Oct 2028 (24, UTC month bounds) plus `opd.emr_record_default`. Each partition has ENABLE + FORCE RLS and the same policy, and no privilege for `sahaj_app` or PUBLIC; the application only touches the parent.

### Consequences the java-developer and the architect must know
- **One record per encounter is not a database constraint.** A unique index on a partitioned table must contain the partition key `created_at`, so it cannot enforce "one per visit". Keep ADR-020 D8: transaction-scoped advisory lock on the encounter id, then find (the indexes above), then insert. QA needs a concurrency test (two simultaneous opens give one row). *Option for the architect/human if this is not acceptable:* partition by the encounter's own date (for OPD the visit's `token_date`) and enforce uniqueness with `(tenant_id, opd_visit_id, opened_on)` plus a composite key to `opd.visit (tenant_id, id, token_date)`; this changes the partition key from the ADR and needs a new migration before any data exists.
- A lookup by `id` alone probes every partition's primary key index (about 25 now, growing by one a month). Prefer to carry the record id from the Queue card (it is already in the visit list). If it becomes slow, archive old months or carry `created_at` in the API.
- A table that points at a record later (SAH-51 addenda) must store `(record_id, record_created_at)`.
- `updated` columns are column-level grants: an unexpected `UPDATE` of another column answers 42501. If the java-developer needs another column, ask for a new migration (`grant update (...)`).
- `sections` is built, validated and size-limited (1 MB at the database, 32 KB per section in the application). It is clinical text: never in a log, audit value or exception message.
- `status = 'SIGNED'` is accepted by the check and by the grants now, so SAH-51 needs no migration for it; nothing in phases 1 and 2 writes SIGNED. A database-level guard that refuses edits to a signed record is not built (SAH-51 defines addenda); the application returns 409 `emr-record-signed`.

### Partition upkeep (automated, DEC-049 item 3, 13 Nov 2026)
No calendar task and no human schedule. Two parts:
1. **Every migrate makes the coming months.** The function `opd.emr_record_upkeep_partitions(p_months_ahead integer default 12)` (migration `V2026_12_13_1000__opd_emr_record_partition_upkeep.sql`) creates, for the current UTC month and the next `p_months_ahead` months, every missing `opd.emr_record_YYYY_MM` through `opd.emr_record_ensure_partitions` (RLS enabled and forced, policy, no privilege for `sahaj_app` or PUBLIC). A Flyway **afterMigrate callback** calls it with 12: the file is `docs/database/SAH-53-partition-upkeep-callback.sql`, to be placed unchanged by the java-developer as `backend/src/main/resources/db/guard/afterMigrate__opd_emr_record_partition_upkeep.sql`.
   - Why a callback: a versioned or repeatable migration runs again only when its checksum changes; a callback runs after every `migrate`, also when nothing is pending, as the migrating user (`sahaj_migrator`). Why `db/guard`: `application.yml` already lists `classpath:db/migration,classpath:db/guard` for dev, test and prod (the dev-tools guard callback is there), and `scripts/validate.mjs db` refuses any file in `db/migration` that is not `V__` or `R__`. No configuration change is needed. The application itself creates nothing.
   - Idempotent: a month that exists is skipped before any lock is taken, so a normal start does nothing. On a fresh database Nov 2026 to Oct 2028 come from the SAH-53 migration (24 months); the callback adds months as the clock moves (Nov 2028 is created once today is in Nov 2027).
   - **Never fails a deploy.** Each month is made in its own sub-transaction. If the default partition `opd.emr_record_default` already holds rows of that month (PostgreSQL refuses the partition, `check_violation`) the month is skipped; if the table stays locked for more than 10 seconds (`lock_timeout` set on the function) the month is skipped. Both give a `RAISE WARNING` (Flyway writes it to the log; the text names the partition, never row data) and a result row `(partition_month, outcome)` with outcome `created`, `skipped_default_partition_has_rows` or `skipped_lock_timeout`. A skipped month is tried again on every later migrate. For the default-partition case a human moves that month's rows out of the default as `sahaj_migrator` (copy to a holding table, delete from the default, create the partition, copy back); the application never does this.
   - Additive: two new functions, no table or data change; `opd.emr_record_ensure_partitions` is unchanged.
2. **The application warns.** `opd.emr_record_future_partition_count()` returns `integer`: the number of monthly partitions that start after the current UTC month (the default partition is not counted; read from the catalog, no clinic data, `SECURITY DEFINER`, `search_path = pg_catalog, pg_temp`, `EXECUTE` for `sahaj_app` only, revoked from PUBLIC). Normal value after a migrate: 12. The java-developer calls it at start-up and once a day and logs a WARN (no row data) when it is under 3: upkeep has been failing, or the application has run for 9 months or more without a deploy or restart. It counts existing months, not an unbroken run, so a gap does not lower it; the callback fills a gap on the next migrate.

## Tenant scope and RLS
Global tables: no clinic. Clinic tables: row level security as above, so clinic A never sees or changes clinic B's departments, versions, doctors, records or usage; with no tenant bound `platform.current_tenant()` is null and nothing is visible or insertable (fails closed). `sahaj_app` cannot bypass RLS. `emr_department_version` has only select and insert policies, so row level security refuses update and delete on top of the privilege and the trigger.

## Retention
Library, starters, starter layouts, department versions: for ever (records refer to them). Departments, doctors: life of the clinic. EMR records: clinical, **never hard-deleted** (no DELETE grant); kept for the life of the clinic in phase 1; the legal retention period is a human decision. Old monthly partitions may be detached for archive only by a human decision. Usage: life of the clinic, no patient data.

## Backward compatibility
- The previous application version (the SAH-43 code on the old schema) cannot run on this schema: the tables it reads (`emr_template*`, `emr_specialty_alias`, `emr_settings`) are gone. That is intended: they never reached `main`, and the java-developer replaces the classes listed in ADR-020 D13.5.
- Against `main` (merged code): purely additive. `opd.visit`: the check is widened (rows of the previous version stay valid, the previous version never writes REVISIT) and a unique `(tenant_id, id)` is added; the previous version does not name it. No existing column or table is dropped or renamed.
- Build lock: `uq_visit_tenant_id` builds an index and blocks writes to `opd.visit` while it builds. Negligible on a small table; on a production table with millions of visits run that one statement as `create unique index concurrently` first (outside a transaction) in a separate release.
