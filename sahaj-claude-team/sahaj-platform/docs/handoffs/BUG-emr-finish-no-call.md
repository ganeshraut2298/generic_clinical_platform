# BUG · EMR "Save draft" and "Complete visit" send no request; no move to the next step; bill not checked

Raised: 19 Nov 2026, human (chat): "after save and complete visit, API is not called; need to call APIs and redirect patient to next flow, also verify the bill." Seen on the live dev platform (General Medicine, test doctor "Dr Test GM Live").
Stories touched: SAH-51 (finish and sign, SAH-51-1, SAH-51-3), ADR-025 (sign outcome), DEC-054 (live OPD journey; earlier draft-save hang).
Branch: current (feature/SAH-39-home-kinetic-background), same shared-tree reasoning as DEC-083 answer 4.

## Tech lead reading (code only; live reproduction was not possible: no access to localhost from this session)
The buttons are wired (emr-record.page.html:220-238 → saveDraft() / complete()). The sign path exists (EmrSignService → VisitService.FinishMove; the frontend then calls afterSign → leave('QUEUE')). There are several silent no-op paths, where no request is sent and no message is shown:
1. `EmrRecordStore.save()` (emr-record.store.ts ~659-669) returns `of(false)` without a message when `readOnly()`, `saving()` or `conflict()` is set. When a dirty section has `problems` it only sets `saveError` (FIX_ERROR); that is invisible if the section is collapsed or off screen.
2. `EmrFinishFlow.begin()` (emr-finish.flow.ts:169-173) returns silently when `starting()` is stuck true, or on readOnly.
3. `saveThenCheck()` (emr-finish.flow.ts:212-228): when the AUTO save returns false, `finishCheck` is skipped, `signError` is null, and nothing is shown. This is the most likely path for "Complete does nothing" when the record has unsaved entries and a hidden field problem, a conflict, or a stuck `saving` flag.
4. `saving()` stuck true after a hung or failed request (DEC-054 hang history) disables Save draft ("Saving") and silently blocks Complete.
