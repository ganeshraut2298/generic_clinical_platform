### ADR-028 design
- **D1 Profiles:** no default (remove `${SPRING_PROFILES_ACTIVE:dev}`); exactly one of dev/test/pilot/prod, else stop before port bind and DB connect (EnvironmentPostProcessor or main); `spring-boot:run` keeps dev via the pom plugin `<profiles>`.
  - dev: bypass loopback only, log sender, trial on, cookie not Secure. test: as today, limits raised.
  - pilot: log sender; datasource from env (`sahaj_pilot`); `/api/**` from outside `SAHAJ_PILOT_ALLOWED_NETWORKS` (private ranges only, required) answers 403 `forbidden`; cookie Secure (`SAHAJ_REFRESH_COOKIE_SECURE=false` allowed only in pilot); start-up log "Pilot profile: test data only. Sign-in codes are written to the log."
  - prod: datasource from env (`sahaj_prod`); exactly one real sender required (none exists, so prod cannot start, BR-5); cookie HttpOnly + Secure + Strict; CORS from `SAHAJ_CORS_ALLOWED_ORIGINS`; remote IP header, protocol header and trusted proxies required.
  - `ProductionStartupGuard` (pilot, prod) names the variable, never the value. Refuses: missing or blank required var; JWT secret under 32 bytes; pepper missing, invalid or equal to the JWT secret; any of otp dev-bypass, admin totp dev-bypass, admin enabled, admin bootstrap, sample admin, owner IPD trial (OQ-77-17: refuse); a dev-tools jar (manifest `Sahaj-Dev-Tools` or `sahaj.devtools`) or a dev-tools/dev-seed Flyway location; `clean-disabled` false; a `*` origin; a limit out of range; prod with the log sender, no real sender, or cookie not Secure.
- **D2 Dev bypass:** only when dev + bypass on + no remote-ip or protocol header configured + no `Forwarded`, `X-Forwarded-For`, `-Host`, `-Proto` or `X-Real-IP` on the request + `getRemoteAddr()` is a loopback literal (`IpLiterals`, as `AdminDevBypass`). Checked on every code request and check, incl. PIN set; otherwise the normal path and nothing reveals a bypass. Controllers pass a `CallerContext` to `OtpService`.
- **D3 OtpSender port (DEC-060 2A exception: sign-in and PIN-set SMS only):** `OtpSendResult send(OtpMessage(mobile, code, purpose, validFor))`, never throws, returns within the timeout; `OtpPurpose {SIGN_IN, PIN_SET}`; `OtpSendResult(sent, FailureClass {TIMEOUT, PROVIDER_ERROR, REJECTED, NOT_CONFIGURED})`. One adapter per provider in `infrastructure.otp.<provider>`, chosen by `SAHAJ_OTP_SENDER`, each its own story after provider + DLT; JDK HttpClient (any SDK goes to the human first); nothing provider-specific in the repo until then. 5 s total (2 s connect), one attempt. Failure: 503 `otp-send-failed`, Retry-After 30, code never usable, counts against caps but not as a wrong code, one WARN on `sahaj.otp` (failure class and request id only). `LogOtpSender` in dev, test, pilot on its own logger `sahaj.otp-log-sender` (mobile masked).
- **D4 Code hardening:**
  - Purpose set by the server from the operation (not in the API): `/auth/otp/*` SIGN_IN; `/me/pin/code` and `PUT /me/pin` PIN_SET; a code of the other purpose answers "That code is not right." and counts as wrong.
  - Client key `ClientKey.of(getRemoteAddr())` after the trusted-proxy rule. Locks per (mobile, client key) for both locks (human to confirm): 5 wrong on one challenge, code dead and pair locked 15 min (CODE); 15 wrong in 24 h by the pair, 60 min (DAY), not reset by a new code.
  - Caps: sliding hour from stored challenges; 5 per mobile (both purposes), 30 per client key; failed sends count.
  - Request order: 400 validation; dev bypass; tx A (`pg_advisory_xact_lock` mobile then client; live lock 423; newest challenge under 30 s 429 resend; mobile cap then client cap 429; insert PENDING; commit); send outside any tx; tx B: SENT (202) or FAILED (503).
  - Check order: advisory lock on mobile; live pair lock 423 even for the right code; newest SENT challenge for (mobile, purpose) `for update` (none: 401 "No code was sent to this number."; PIN set 400 "Send a code first."); dead, used or expired: 401 "That code has expired. Request a new one."; wrong: `failed_count = failed_count + 1` (+ `locked_at` at the limit) guarded by `consumed_at is null and locked_at is null`, insert `otp_failure`, count the pair's 24 h failures, set the lock, answer DAY 423 / CODE 423 / 401, commit with `noRollbackFor`; right: `consumed_at` only where null and not locked, 0 rows means 401 expired (one of two simultaneous right codes wins).
  - A lock writes one `sahaj.security` line (kind, client IP, request id; never the mobile). Hourly purge of OTP rows older than 48 h.
  - Residual risk: anyone who knows a mobile can use its 5 requests an hour and delay that person's next sign-in by up to an hour; open sessions are unaffected.
- **D5 Sessions:**
  - New tenant table `auth_session`, one row per sign-in; `started_at` = code verification (the selection token carries `auth_time`); `absolute_expires_at` = start + 14 h.
  - Access JWT gets `sid`; `exp` = min(15 min, absolute end). A token without `sid` answers 401 `unauthorized` (everyone signs in once after the deploy).
  - `JwtAuthenticationFilter` 60 s cache by `sid`: ended, 401 `unauthorized`; absolute reached or idle 30 min or more, end it (ABSOLUTE or IDLE), revoke its refresh tokens, 401 `session-expired`.
  - Last use: every authenticated request except `POST /auth/refresh` and requests with `X-Sahaj-Activity: background` (Angular sends it on timer polls; add to CORS); written at most once a minute (`where last_used_at < now() - 60s`), no index.
  - Refresh: legacy token without `session_id`, 401 `session-expired`; lock the session row; ended, 401 `unauthorized`; limit reached, 401 `session-expired`; else rotate with the same `session_id`, expiry = absolute end, cookie Max-Age = time left. Never extends, not counted as use.
  - End reasons REUSE, LOGOUT, LOGOUT_ALL (self policy across clinics), MEMBERSHIP (within a minute). No screen lock, no new text (OQ-77-9, -10).
- **D6 Proxy and HTTPS:** RemoteIpValve `remote-ip-header` from `SAHAJ_REMOTE_IP_HEADER`, new `protocol-header` from `SAHAJ_REMOTE_PROTOCOL_HEADER`, `internal-proxies` from `SAHAJ_TRUSTED_PROXIES`; first-from-right non-trusted address; an untrusted caller's header is ignored; `TrustedProxyStartupCheck` covers the protocol header. Access log adds `clientIp=`; timestamp with UTC offset. HSTS `max-age=31536000`, includeSubDomains off until ops confirm (`SAHAJ_HSTS_INCLUDE_SUBDOMAINS`), no preload. CSP is a separate story.
- **D7** new migrations `V2026_12_17_*` or later, `outOfOrder` false. **D8** trial off in pilot and prod (guard refuses); `ipdTrialAvailable` false, `/modules/ipd-trial` 404; the only switch is `runbook-ipd-on.sql`.
- **D9 keys (default, range):** `SAHAJ_SESSION_ABSOLUTE_LIFETIME` 14h (1h-24h); `SAHAJ_SESSION_IDLE_TIMEOUT` 30m (5m-60m); `SAHAJ_SESSION_LAST_USE_WRITE_INTERVAL` 60s; `SAHAJ_OTP_CODE_TTL` 5m; `SAHAJ_OTP_RESEND_AFTER` 30s; `SAHAJ_OTP_CODE_MAX_WRONG` / `_CODE_LOCK` 5 / 15m; `SAHAJ_OTP_DAY_MAX_WRONG` / `_DAY_WINDOW` / `_DAY_LOCK` 15 / 24h / 60m; `SAHAJ_OTP_REQUESTS_PER_MOBILE` / `_PER_CLIENT` / `_REQUEST_WINDOW` 5 / 30 / 1h; `SAHAJ_OTP_SEND_TIMEOUT` 5s; `SAHAJ_OTP_SENDER`; `SAHAJ_REMOTE_PROTOCOL_HEADER`; `SAHAJ_CORS_ALLOWED_ORIGINS`; `SAHAJ_PILOT_ALLOWED_NETWORKS`; `SAHAJ_REFRESH_COOKIE_SECURE`; `SAHAJ_HSTS_MAX_AGE` / `_INCLUDE_SUBDOMAINS`. No new library.
