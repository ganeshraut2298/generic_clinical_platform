## Fixtures and conventions
- A record takes a specialty layout through the existing header switch (`switchDepartment`), so the profile is the record's starter key (ADR-023 D1). The oncology fixture saves weight and height, fresh normal labs, ECOG 1 and the decision "Give as planned"; with the protocol Paclitaxel 3-weekly (no vesicant) all nine checks pass; AC adds the tenth check (line ready for vesicant).
- Numbers are worked by hand from the contract: BSA = sqrt(height x weight / 3600) to 2 decimals (160 cm, 60 kg: 1.63); calculated = dose per m2 x BSA x level / 100 to one decimal (paclitaxel 175 x 1.63 = 285.3, rounded to the 10 mg step 290; at 90 percent 256.7, rounded 260; doxorubicin 60 x 1.63 = 97.8, rounded to the 5 mg step 100); paediatric dose mg = min(maximum, round(kg x mg/kg)) and ml = mg / mg-per-ml to one decimal (11 kg paracetamol 120 mg/5 ml: 165 mg, 6.9 ml).
- Role tests use real members of the clinic (token and membership agree) and a role claim that disagrees (`tokenClaiming`) for the "menu is not protection" rule.
- Throwaway data only; marker words (`Zxq...`) for leak checks.

## 5. Findings (to be reported, not silenced)
- **F-1 (contract, architect)** `GET /emr/chemo-checks` is "newest first" in opd.yaml but oldest naming first in the database design, the index and the code. The test does not fix an order; the architect should align the contract with the design.
- **F-2 (contract, architect)** The chemo order's confirmed fingerprint does not cover the allergy, consent and scheme flags themselves, only whether their check passes. A doctor who changes "New consent signed today" or the scheme between PREAUTH_RAISED and APPROVED after the second check does not clear the confirmation. This follows "the fingerprint is what the checker is shown" but the checker's summary lists the check texts; the architect should confirm that is intended.
- **F-3 (human, patient story)** The patient API has no date of birth, so the child's age, the vaccine states DUE_TODAY and OVERDUE, the weight centile note, the milestone age band by age and the dental Child tab cannot be reached over HTTP. Tests for those rules are not written (they would be vacuous); only the "not recorded" degraded behaviour is tested. Needs a patient story.
- **F-4 (tests that depend on parallel java work)** `pegfilgrastimSuggested`, `oncReferrals` (8), `oncTakeHome` (6), the five oncology systems, the GM General line, outcome scales and `hiddenSectionKeys` are tested against 0.5.1; they fail until the java-developer's D13 build lands. The Second checks menu key tests (`EmrSpecialtyReferenceIT`) fail until `NavigationPolicy` and `MeService` add the key.
- **F-5 (existing test changed)** `StaffPinIT` expected the PHARMACIST menu with IPD off to be exactly `["today"]`; it is now `["today", "secondchecks"]` (platform.yaml 0.1.1). `MeServiceTest` and `NavigationPolicyTest` (java-developer) may need the same, and the Simple-menu length test of `SetupAndShellIT` (at most 6 items) should be checked by the java-developer for an owner with doctor details.
- **F-6 (not testable)** A wrong try that fails closed with 503 `pin-check-failed` is the platform's answer (`StaffPinColleagueHttpIT`); forcing it here needs the platform test seam and was not duplicated.
- **F-7 (data)** The seeded chemotherapy doses, vial steps, weight bands and immunisation windows are mockup values, not clinically reviewed; a clinical reviewer must check them before real use (DB design question 1).

## 7. How to run
1. Recreate `sahaj_test` (`node scripts/setup/create-database.mjs`), then `mvn -f backend/pom.xml verify` or `node scripts/validate.mjs all`.
2. Run first: `ChemoOrderTableIT`, `EmrPhase4TablesIT`, `RowLevelSecurityCatalogIT`, `CoursePaymentsIT`, `EmrChemoOrderIT`, `EmrChemoPinIT`.
3. A failing test is reported to its owner (java-developer for behaviour, solution-architect for the contract, db-engineer for a migration); it is not deleted or skipped.
