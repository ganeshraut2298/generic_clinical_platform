## How time, people, the PIN and the database are handled
- **The clock seam.** The MAR decides "today", due, late and `doseCount` with the database clock read through `MedicineOrderRepository.databaseNow()` (and the Nursing sheet through `VitalsRepository.databaseNow()`). The classes that extend `MarSupport` run in their own Spring context with those two calls replaced by a Mockito spy bean (`@MockitoSpyBean`) that answers a fixed instant when a test calls `clockAt(...)` and the real database clock otherwise. Nothing else is replaced: the admission lock, the insert, `recorded_at`, the guard trigger and every constraint run on the real database. The spy is reset after each test.
- **Orders for a fixed clock.** A fixed clock on today's IST date needs orders that were verified long before it (or the "verified today" rule of AC10 would depend on the real time of the run). `activeOrder` places and verifies through the real endpoints and then sets `ordered_at` / `verified_at` to the day before as the table owner with `trg_medicine_order_guard_update` switched off in one committed transaction (the column cannot be written by the application). The AC10 tests set the verification time on purpose (`verifiedAt`).
- **People.** As in SAH-31 (`PinTestSupport.staff`): real sign-ups with a membership in the clinic and a real PIN set through the real endpoints; the pepper is random per run (`@WithPinPepper`).
- **Races** are forced: a second connection holds the admission row, each request is started and seen waiting in `pg_stat_activity`, then the lock is released. The wristband stop is answered in the first transaction (no lock), so that pair is started together instead.
- **Database errors** (23505, 23514, 23503) are forced by a trigger the table owner creates and drops for one clinic; the **real guard trigger** is reached by changing `ipd.drug.high_alert` of one medicine behind the application's cached catalogue (restored in a `finally`).
- **Texts** are written in the tests from the contract and the ADRs, not read from the code. The GET `403` text "You cannot open the medicine round." is a build-time choice of the java-developer (DEC-018), not in the contract. `sahaj_test` is not cleaned; every test uses its own new clinic. The full suite has 26 skipped tests that existed before this story (conditional on the dev-tools profile / external tools); none was added.

## Findings and open points (for the owners; none is a failing test)
Status after the review fix pass (6 Nov 2026):
1. **Scan limit (was: ADR / story say 40, contract regex allowed 41) - FIXED in code (review R2 / S6).** The deny-entry shape is now `^[A-Z]{2,6}-[0-9]{5,9}$` (8 to 16 characters), so a mobile number, an ABHA-like number or a longer digit run is only shown as "text that is not a UHID". The tests follow the code (`DoseGiveIT.aUhidShapedScanIsWrittenAsTypedUpToNineDigitsAndNotMoreAndNeverAnythingElse`). Still open for the architect: align the ADR-011 D4 / story AC6 / contract regex wording with the 16-character shape.
2. **Replay of a high-alert dose compares the second nurse by display name** (R1, DEC-018, backlog): two nurses with the same display name would look the same on a replay. Not testable without duplicate names; platform to add `userId` to `TeamMember`. Open.
3. **AC9 (no access row on opening the MAR) is superseded by ADR-011 D10**; the tests follow the contract. Human to confirm DEC-018 item 5 (R4). Open.
4. **Read-only refuses recording a dose** (AC11) while Stop stays allowed; the tests follow the story. Human to confirm DEC-018 item 4. Open.
5. The GET `403` text "You cannot open the medicine round." is not in the contract (R3); the test pins it. Open for the architect.
6. The colleague limiter is in memory and uses the application clock (HARD-2, S1, S2, R5). The 24-hour bucket cannot be aged without a seam, so the tests empty only the 15-minute bucket. Open (go-live).
7. **A colleague's wrong-PIN answer carried a tries-left count (S4) - FIXED.** The second nurse's answer is now "That PIN is not right." with no digit; the audit row and the check outcome still carry `triesLeft`. Own-PIN answers keep the count (`PharmacistCheckIT`, `StaffPinCheckIT`, `MedicineReviewFixIT` unchanged and passing).
8. **MAR and `doseCount` loaded every order (R7) - FIXED.** Only PENDING / ACTIVE orders are read; `MarReadIT.aStoppedAndARejectedOrderNeverAppear...` proves Stopped and Rejected orders are absent from the MAR, the Nursing sheet GET, the vitals save and the dose answer, and that a Stopped order's dose is still in the EMR `lastDose`.
9. Not tested here because they are decisions or front-end work: S3 (event text "wristband scanned" when the UHID may have been typed; human decision), S5 / R8 (no limit on mismatches; HARD-2).
