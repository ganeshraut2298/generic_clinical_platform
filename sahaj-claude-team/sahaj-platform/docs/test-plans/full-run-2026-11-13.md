### M1 Treatment course creation rejects a sitting without `items` (52 tests)
- Evidence: `Response status expected:<201> but was:<400>` at `EmrPhase3Support.newCourse:351 -> okKeyed:324`. Body: `fieldErrors[0] = sittings[0].items: "Send the items as a list."` The same message is why `EmrCoursePlanIT:160` sees `sittings[0].items` where it expects `sittings[0].chargePaise`, and why two role tests answer 400 where they expect 403 (`EmrCoursePlanIT:208`, `EmrSpecialtyCoursesIT:181`: the 400 comes first).
- Cause: `TreatmentCourseService.cleanItems` (line 706) treats `items == null` as an error. In `docs/api/opd.yaml` `CourseSittingPlanInput` only `addOptionKey` is required; `items` is optional (line 4076-4083). `cleanItems` is right for the change input (`items` required there, line 4089+), wrong for the create plan loop at line 674.
- Fix: at line 674 pass `plan.items() == null ? List.of() : plan.items()`.
- Tests: ChemoOrderTableIT 13 (:100,117,139,154,171,195,221,242,258,272,302,322,353), CoursePaymentsIT 17 (all), EmrCourseAdmissionIT 5 (all), EmrCoursePlanIT 9 (all), EmrPhase3TablesIT 2 (:286,:473), EmrSignProfilesIT 3 (all), EmrSpecialtyCoursesIT 3 (:138,:158,:181).
