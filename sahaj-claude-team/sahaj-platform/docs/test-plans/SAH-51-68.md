## Fixtures and conventions
- Everything goes through the real endpoints as `sahaj_app`; the few direct SQL statements are the ones no endpoint exists for (an expired hold, a record signed by the fixture update, the probes of the table tests, which run in rolled-back transactions).
- `signRecord` (the SAH-53 fixture that marks a record signed by SQL) now writes the signer membership and a sign key and clears the hold, because `ck_emr_record_signed_complete` and the immutability trigger require it; a record is signed last.
- Made-up names and mobile numbers only; marker words (`Zxq...`) for leak checks. No patient name, mobile, DOB or clinical note is put into a log line by a test.
- Specialty effect blocks are asked for with the finish check on a record that is not ready: the check answers `effects` whether or not it is ready, so no specialty record has to be filled in.
- Concurrency tests use two threads released by a latch and assert the invariants (one winner, no 500), not an order.

### 7.3 Connection pool (H37)
The order pre-check of an IPD round sign runs and commits in its own short transaction before the sign transaction opens (H37), so one sign holds one pool connection at a time. The test profile's request pool is `maximum-pool-size: ${SAHAJ_DB_POOL_SIZE:5}` (`backend/src/main/resources/application-test.yml:13`); production is 10. EmrIpdRoundFinishIT.asManyRoundSignsAtTheSameMomentAsThePoolHoldsAllFinishWithoutAConnectionTimeout signs 5 admissions' round notes at the same moment (N = 5, the test pool size) and expects five 200 answers inside 25 seconds (the Hikari connection timeout is 30 seconds), five notes and five orders. Not run (no database). If `SAHAJ_DB_POOL_SIZE` is set below 5 the test is still valid (it needs the pool not to be exhausted by the signs themselves). No IT calls `EmrIpdOrderPort.checkRecorded` and no IT counts transactions per sign (the counts are asserted in the unit test EmrSignServiceTest: 1 plan transaction before the check, 2 in all).
