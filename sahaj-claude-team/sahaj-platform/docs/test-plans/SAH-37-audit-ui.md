# SAH-37 release audit, phase 2: UI glitches and layout (measure pass)

Story: SAH-37 IPD patient card setup. Decision: DEC-032 (phase 2). Date: 9 Nov 2026. Author: qa-engineer.
This pass only MEASURES and reports. No product code was changed. The angular-developer fixes the defects below.
No Sev-1 or Sev-2 defect is deferred; every one of them has a fix owner.

## 1. What was measured and how

- Build: the existing production build (`frontend/dist/frontend/browser`, newer than every source file, so no rebuild), served by `frontend/e2e/serve.mjs` on port 4337.
- API: mocked in the browser with the existing world files (`sah31-world.ts`, `sah32-world.ts`, `sah37-world.ts`). Nothing real was called. Every run ended with `w.unmocked = []` except the Overview tile (see 5.2).
- Sizes: 1920x1080, 1366x768, 1024x768, 768x1024, 375x667, 125 % zoom of 1920 (1536x864 at dsf 1.25) and of 1366 (1093x614 at dsf 1.25), the dark theme at 1366 and 375, plus one extra size, 1150x800, added after the first runs showed a layout band problem (D-1).
- Screens and states: setup page (Layout and sections, Fields, Quick actions, clean v1, saved draft, unsaved edits, read-only IPD, a non-owner, loading, load error with retry, publish busy, save conflict 409, save offline, preview with no patients), the Published versions list, the leave dialog (ESC, backdrop, Tab, Enter, focus return), the Admitted tab in Compact, Standard and Expanded (owner and doctor; loading, error, empty), and the Overview tile.
- Instruments (one pass over the DOM per screen): sideways scroll, clipped or ellipsised text, children spilling out of their parent, off-screen elements, wrapped labels, touch size, accessible names and tooltips, duplicate ids, contrast (computed, then every failure re-checked against real pixels of a screenshot), tab order and focus ring, sticky overlap with `elementFromPoint`, layout shift (PerformanceObserver), the sequence of what the page shows while loading, console (error and warning), page errors, failed requests, HTTP status 400 and above, duplicate GET calls.
- Throw-away tooling: `frontend/e2e/audit-sah37-ui.spec.ts`. It does nothing unless `AUDIT_UI=1` (so `npm test` and `validate all` skip it) and asserts nothing about the product. It lints clean. Raw findings (JSON lines, about 16,000) are in the scratchpad `audit-ui/out2.jsonl`, `out3.jsonl`, `out5.jsonl`.
- Screenshots: `docs/test-plans/SAH-37-audit-shots/` (52 files, 13 MB), every screen at 1366 and 375 px. Full-page shots repeat sticky elements (the status bar and the header) at odd places; that is a screenshot artefact. The `-realistic` and `sticky-*` shots are viewport shots. Shots named `*-375` for the saved-draft screens were taken with the deliberately long test label (see D-5), so they are as wide as 652 px; the `-realistic` shots use normal labels.
- Limits: (a) ExpressionChangedAfterItHasBeenChecked cannot be observed in a production build (the check is compiled out). The count is 0 here but that proves nothing; the unit tests run in dev mode and are the place for it. (b) A real mouse drag (HTML5 drag and drop) was not exercised; the arrow buttons were. (c) The Check and Critical tile marks were measured in the light and dark theme on the five vital tiles only. (d) Screen readers were not run.

## 3. What was clean

- Console, all sizes, themes and zoom: zero page errors and zero unhandled rejections. Errors and warnings only appear where the test forced a failure (500, 409, lost connection), as the browser's own "Failed to load resource" line. Zero 404s for assets (fonts, scripts, styles). Zero ExpressionChanged (see the limit in 1).
- Duplicate calls: none on load. The setup page makes exactly one `GET card-setup` and one `GET admissions?cardFacts=all`; the Admitted page one `GET admissions`. The only repeat is the Try again click.
- Loading and error states: the setup page shows "Loading the patient card" and then the screen, with no empty frame in between (state sequence: loading, then bar and preview in one step); the load error shows the message with "Try again", which recovers; a failed save shows "We could not save the draft. Try again."; a 409 shows its notice with Reload; Admitted shows the page error with "Try again" and no tabs. No flash of an empty table before data: "No one is admitted right now" never appeared before the cards. No empty-state glitch with no patients in the preview (the example patient shows, as in the mockup).
- Leave dialog: opens at once with focus on "Stay on this page" (the safe choice), Tab cycles between the two buttons, ESC and a backdrop click close it and keep the page and the edits, focus returns to the Overview link, Enter on the focused button works, the dialog is above the sticky bar, the title is the dialog label. Width 420 px (full width at 375), no scroll needed, no content jump.
- Keyboard: Tab order follows the visual order (status bar buttons, tabs, panel, rows, then the preview, then the page ends); the tab list uses a roving tab stop; a disabled Save draft is skipped; every focus stop had a visible ring (0 stops without a ring in all runs); no focus on a hidden element.
- Layout otherwise: no sideways scroll on any setup or Admitted screen with realistic labels at 1920, 1366, 1024, 768, 375 and both zooms; the 125 % zoom matches its width in CSS pixels; columns of switches, pills and arrows line up on one right edge on every row (switch right edge 805 or 816 on all rows); row heights are consistent; the sticky status bar sits correctly at 1920 and with a clean setup at 1366; the preview collapses to one column at 1100 px and below, and the cards-per-row control is hidden on phones, as the mockup does.
- Buttons: the status bar order is Reset to default, Discard draft, Save draft, Publish (primary on the right) with 44 px height; the busy state disables all four and the label changes to "Publishing"; the leave dialog puts Leave (primary) on the right.
- Formats: "9 Nov 2026, 11:05 AM IST" in Published versions, "saved 11:05 AM" in the draft pill, "4 Nov 2026, 9:20 AM IST" on the card, "Compact · customized · v2 · draft" on the Overview tile (tile 115 px high like its row; not clipped). Amounts use `₹3,000` and `₹10,000` (see 4.4).
- Theme: no hard-coded colour in the SAH-37 files (scan of `features/config/ipd/ipcard/*`, `features/ipd/admitted/*`, `features/ipd/card/*`). The dark theme works on every screen. The Check and Critical tile marks and the tile values pass AA in light and dark.
- Dropdowns: View as defaults to Nurse and Patient to the first patient, as the mockup (`pv:{role:'nurse'...}`); the two selects are 44 px high and labelled.
- Role and state screens: IPD read-only (all controls off, notice shows), a doctor (notice, controls off, no Customize card link), no patients, publish busy: all render without clipping at 1366 and 375.

## 4. Mockup conflicts and open questions (not guessed; the human decides)

1. **Split breakpoint (D-1).** The mockup collapses the split at 1180 px (`@media (max-width:1180px)`, mockup line 2181); the app at 1100 px. Both are wrong in practice because the page sits inside the 248 px rail and the setup menu; the editor is under 330 px up to about 1300 px. A fix means a breakpoint or a container query that the mockup does not have.
2. **Phone rows (D-2).** The mockup has no rule for the editor rows on a phone. A wrap of the row (label on its own line, switch and arrows below) is a design change.
3. **Contrast tokens (D-9).** `--ink-3` and the pill colour pairs come from the mockup and `docs/design/tokens.md`. Reaching 4.5:1 needs darker tokens, which only a human may change.
4. **Rupee format.** `CLAUDE.md` writes "₹ 1,25,000" (with a space). The mockup writes "₹50" and the shared formatter `shared/format/inr.ts:15-17` writes "₹1,25,000" (no space). The screens follow the mockup. Not counted as a defect; the project rule and the mockup disagree.
5. **Fourth tab Workflow stages.** In the mockup, not built, documented as OQ-37-3. Not a defect.
6. **Touch size.** The mockup uses 36 to 38 px controls; the app uses 44 px (DEC-013 item 4, accepted). D-12 lists only what is under 44 px.
7. **Deviations to restore (no human decision needed, the mockup is clear):** D-3 (bar static on phones), D-4 (BP tile), D-15 (view labels hidden on phones).
