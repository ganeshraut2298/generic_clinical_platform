## 1. How the tests are built and run

| Where | What | Runs in |
| --- | --- | --- |
| `backend/src/test/java/com/sahaj/platform/it/` | ITs that need no dev-tools class: `PackagedJarDevToolsIT` (T13), `DevSampleAdminAbsentInProductionIT` (T2), `DevToolsGuardCallbackIT` (T18 guard), `DevToolsCleanupScriptIT` (T19 with a real `psql`), `DevSampleAdminFunctionIT` (T14, A1 to A8 of the db note) | every `mvn verify`, normal build and `-Pdev-tools` build |
| `backend/src/test/java/com/sahaj/platform/it/devsample/` | Helpers (not tests): `AppRun` (starts the whole application in the test JVM exactly as `java -jar ... --option=value`, on a random loopback port, against `sahaj_test`, Flyway off unless asked, keeps every log event), `RawHttp` (socket HTTP client: exact header names, repeated headers, hostile `Host`), `SampleAdminDb` (JDBC state, preconditions, snapshot and clean-up), `PsqlRunner` | - |
| `backend/src/devtools/test/java/com/sahaj/platform/devtools/it/` | ITs that need the dev-tools classes: `DevSampleAdminSwitchesIT` (T1), `DevSampleAdminRequestChecksIT` (T4, T5, T16), `DevSampleAdminFailureLogsIT` (T11), `DevSampleAdminNonceLogIT` (T17), `DevSampleAdminEndToEndIT` (T6 to T11, T15), `DevToolsCallbackPreflightIT` (T18 L1), `DevToolsCleanupAfterCallbackIT` (T19 part 2), `PackagedJarDevToolsBuildIT` (T13 positive control) | only with `-Pdev-tools` (the folder is added to the test source set by the profile) |

Why `AppRun` and not `@SpringBootTest`: condition C2 reads only the `commandLineArgs` property source, which a Spring test context never has. `AppRun` passes real program arguments, sets and restores real JVM system properties, simulates an operating-system variable by replacing the `systemEnvironment` source with a copy plus the variable (what Spring Boot's cloud detection and relaxed names read), and excludes classes under `test-classes` from component scanning (a test context does this for you, a plain run does not).

Commands (all under the backend lock):

```bash
# 1. unit tests of both source sets (2,193 tests incl. 88 dev-tools unit tests)
mvn -f backend/pom.xml -Pdev-tools test
# 2. the dev-tools ITs (package runs before failsafe in verify, so the jar exists; output goes to backend/target-devtools)
mvn -f backend/pom.xml -Pdev-tools verify -Dtest=NoSuchTest -Dsurefire.failIfNoSpecifiedTests=false "-Dit.test=Dev*IT,PackagedJar*IT"
# 3. the normal build (this is also what `node scripts/validate.mjs backend` runs, so T13 is part of the gate)
mvn -f backend/pom.xml verify
```

`package` runs before `pre-integration-test`/failsafe in `verify` (Maven lifecycle), so the jar exists when T13 runs; this was confirmed by the runs below. `-DskipTests`, `-DskipITs` and `-Dmaven.test.skip=true` skip T13: H-DEV-8 (the same check in `scripts/validate.mjs backend`) stays a recommendation to the human.

`-Pdev-tools package` and `-Pdev-tools verify` were allowed and worked (jar `backend/target-devtools/sahaj-backend-devtools-0.1.0-SNAPSHOT.jar`).

### Notes on the specification (for solution-architect)

- N1 · T10 says "exactly one 201, nine 404" for 10 parallel calls. With the rate limit of D6 (5 gate-passing calls per 15 minutes) calls 6 to 10 answer 429 even though they passed the gate, so at HTTP level the others are 404 or 429. The HTTP test asserts exactly one 201 and the rest in {404, 429}; the "one wins, nine lose" race is asserted at function level (10 sessions, no limiter).
- N2 · T5 lists a `%2F` path. Tomcat answers a percent-encoded slash with its own 400 before any application filter (default setting), so the reserved-path filter cannot answer it; the unit tests cover the decoded-path logic. Not a defect (the request is refused either way) but the 400 differs from the 404 of every other refusal; it reveals only that the container rejected the URI, nothing about this endpoint.
- N3 · C4 Kubernetes detection in Spring Boot 3.5 reads only the real `systemEnvironment` source (not the command line), so the IT simulates the variables by replacing that source.
- N4 · "Skip only on the precondition" is honoured: the only other `assume` is the "stands down in the other build" of the two production-only tests (P6), named in their message.
