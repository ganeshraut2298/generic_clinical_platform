Gaps and notes (SAH-12)
1. The "insert lost the race" branch (`insertVersionIfAbsent` returns false) and the "draft equals live" branch both end in the same 409 `workflow-conflict`. A test cannot force which one a loser takes (it depends on whether the winner committed first). The race tests therefore assert the outcome that holds for both (200 plus 409s, one version, one audit) and run 2 and 4 callers. A deterministic test of the first branch would need a hook in the service (not added; app code is not changed by QA).
2. Mockup parts "What changes when you publish" and "Use recommended" are not built (human decision, in BOARD.md); no test.
3. Angular and browser: the queue board with legacy columns, own-version moves and the 409 handling is checked in `frontend/e2e/app-shell.spec.ts` with a mocked API (see below).

Browser (Playwright, API mocked): `app-shell.spec.ts` "Queue board": columns follow the published steps; a card moves with its button (PATCH body `{stage}`); a refused move shows the server message; a load failure shows an alert; a visit on an older version keeps its legacy Vitals column and its own next step; the board sits in a size container, no column narrower than 210 px, no page overflow at 360 px and 1440 px; no inline `style` attributes in the board.
