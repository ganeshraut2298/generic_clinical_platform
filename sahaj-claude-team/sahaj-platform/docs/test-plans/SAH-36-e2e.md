## How the tests work

- The backend is **not** running. Every call is mocked with `page.route()`; the list answer is copied from the contract. The mock builds each row as the server would for the role: `forRole(role, rows)` leaves the `clinical` property **out** for FRONT_DESK (and every role without it), never `null`.
- The server clock of the list is `2026-11-06T05:47:00Z` (11:17 AM IST); all minutes and "Day 1 (today)" come from it. One test sets the device to 2031.
- The 60-second reload uses `page.clock`; the hidden-tab test uses `HIDDEN_SWITCH`.

## Findings

**F-1 (app, medium, FIXED in the second fix pass, developer-verified, not re-run by QA; see the end of Runs): Transfer from a card can leave the focus on the sheet's close button instead of the "Move to another bed" row.** `AdmissionDialogComponent.applyStartView` sets `focusMoveWhenReady`, and `focusMoveRow` runs from the answer of the free-bed read (or its error). The dialog's own opening step (autofocus of its first control, after the opening animation) runs later when the answers are quick, and takes the focus back. Evidence: with the free-bed read answering at once the select `#ad-bed` is not focused (the active element is the sheet's X button, `mdc-icon-button`) in one of two runs with a free bed and in every run with no free bed (`#ad-move-row`); with the read delayed by 800 ms the focus lands on `#ad-bed` every time. Real networks that answer in under about 150 ms will show it. AC 47 says the part is "open and focused". Owner: angular-developer (`admission-dialog.component.ts`: set the focus after the dialog has finished opening, for example `dialogRef.afterOpened()`, or give the dialog `autoFocus: false` when started from a card). The tests stay red until this is fixed; they were not loosened.

**F-3 (FIXED, test passes 6 of 6; was: app, low, pre-existing): at 360 px the Table view makes the page scroll sideways by 437 px.** The table is wrapped in `.iptbl { overflow-x: auto }`, but the screen-reader-only text "Open" of the last column header (`.sr-only`, `position: absolute`) is placed outside that box (its containing block is an ancestor), so the document grows. The markup and the style are identical to the table before SAH-36 (checked against `git show HEAD`), and AC 2 says the table is unchanged, so this is not a regression of SAH-36; it is listed because the Table view is now one tap from the default view. Owner: angular-developer (give `.iptbl` `position: relative`, or make the header cell the containing block).

Observations (not defects):
- The "+N" chip is reachable only by tooltip or screen reader, so on a tablet the folded flags cannot be read (known, DEC-021). The tests assert its tooltip text and its screen-reader text.
- At 700 px and below the "Cards per row" switch is not shown at all (the mockup makes every setting one per row). AC 1 says the switch is shown in Cards view; the tests follow the CSS rule and assert it is hidden at 360 px.
- The flags line takes the first of the non-safety flags when the card has no safety flag; with a safety flag all non-safety flags fold (`FLAGS_BEFORE_FOLD = 1`). A FRONT_DESK card with Going home today and Deposit low shows the first and "+1" for the second; the Deposit low flag is therefore not drawn as a chip for that role.

Suggested fix for the owner: open the dialog with `autoFocus: false` when `startView` is `move` (in `ipd.page.ts`, `openById`), or move the focus one step later (for example after `dialogRef.afterOpened()` plus a macrotask or a second render).
